# 审核 LaTeX 技术示意图

按“逻辑正确 → 布局清楚 → PDF 验证”的顺序处理示意图。不要用视觉美化掩盖错误的依赖关系。

## 1. 先确定图要说明什么

在改 TikZ 前，读取以下材料：

- 图注；
- 图前、图后的正文；
- 图对应的公式、伪代码或实现代码；
- 必要时读取引用来源或同章术语定义。

先用一两句话写出图的表达契约，例如：

> 图比较纯加法写入与 Delta Rule。两者都保留旧状态；Delta Rule 额外读取旧值、计算误差，再把修正量加回状态。

若这些材料互相矛盾，继续查找项目内证据。仍不能确定时，向用户说明歧义；不要先改图。

## 2. 核对图的逻辑

逐条检查节点和箭头：

1. 确认每个节点代表输入、状态、变换、判断、结果还是注释。
2. 确认每根箭头的源点、终点和含义：读取、写入、控制、传递、旁路或反馈。
3. 核对因果顺序，避免箭头反向或暗示不存在的依赖。
4. 核对状态版本，例如不要混淆 $S_{t-1}$、中间修正量和 $S_t$。
5. 核对分支与合流：共享输入可以分叉，独立结果不可无说明地合并。
6. 核对图中文字、符号、公式与正文术语一致。
7. 核对对比图的边界，避免两个机制看起来像同一条连续流程。

修正逻辑错误后，再进入视觉调整。不要只因为线路难画就改变技术含义。

## 3. 调整布局与箭头

默认保持现有箭头尖的大小、形状和样式。除非用户明确要求，否则不要通过缩短或缩小箭头尖解决问题。

优先使用以下方法：

- 增大节点的横向或纵向间距，让箭头尖之前存在清楚可见的箭杆；
- 允许图变高、变宽，不以紧凑为目标；
- 多根线进入同一节点时，使用不同入口，如 `west`、`north`、`south`；
- 为残差、反馈和旁路设置独立通道，并在含义不明显时加短标签；
- 把标签移到线路之外，避免用文字或白底节点截断箭杆；
- 拉开框与转折点，避免箭头尖贴框、线沿框边运行或穿过节点；
- 两个独立机制确实难以并排阅读时，再拆成上下或左右面板。

遵守以下限制：

- 不要为了绕开一个节点制造横跨整幅图的复杂回路；
- 不要让两根箭头在终点前重合，只留下多个三角形；
- 不要让连接线与框线重合，看起来像框的一部分；
- 不要让箭头标签遮住线路；
- 不要仅凭 TikZ 坐标判断间距足够。

## 4. 聚焦编辑

- 只修改目标图及其必要样式，保留正文、公式、图注和其他图。
- 保留项目已有的颜色、字体、线宽和箭头风格。
- 优先移动节点和路径控制点，避免全局更改箭头样式。
- 在混合工作区中先查看 scoped diff，保留用户已有修改。

## 5. 编译并检查实际 PDF

每次有意义的调整后：

1. 使用项目规定的 LaTeX 引擎编译。
2. 若实时预览或其他进程可能竞争输出文件，使用独立 jobname 和输出目录验证。
3. 将目标 PDF 页渲染为 PNG。
4. 同时检查整页和放大后的目标图，不以编译成功代替视觉检查。
5. 检查：
   - 每根箭头是否有可见箭杆；
   - 方向和端点是否正确；
   - 是否穿框、贴框、压字或相互重叠；
   - 分支、合流、旁路是否一眼可辨；
   - 图注、正文和分页是否受影响；
   - 是否出现溢出、未定义命令或影响成品的警告。

若渲染仍混乱，返回逻辑和布局层重新处理。不要连续堆叠局部补丁；必要时撤回到最后一个清晰版本再重新布局。

## 6. 交付

说明：

- 图要表达的逻辑；
- 修正了哪些逻辑或线路问题；
- 是否保持箭头尖样式不变；
- 编译和 PDF 视觉检查结果；
- 仍需用户判断的取舍。

一次处理多张图时，先列出图表清单，再逐张完成“逻辑核对 → 修改 → 渲染检查”，不要只看一张联系表就宣称全部通过。

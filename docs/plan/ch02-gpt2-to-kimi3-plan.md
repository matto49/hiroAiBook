## 一、开场：AI 酱已经会扮演佑芽了

### 场景功能

开场只完成三件事：

1. 让读者亲眼看到如今 AI 聊天能力的进步；
2. 让千奈和佑芽自然提出“AI 怎么变聪明了这么多”；
3. 给广提供一个收束技术问题的机会。

开场聊天不负责解释 KV Cache、Delta Rule 或 KDA，也不需要在后文逐节复用。

### 场景

放学后的活动室或空教室。

广把最新模型打开，让它扮演佑芽，与真正的千奈聊天。屏幕上先不突出模型名称，只让读者看到对话。

### AI 佑芽与千奈的聊天草案

```text
千奈：这周末，如果我们三个人一起出去，花海同学想去哪里呢？

AI 佑芽：游乐园！

千奈：很不错呢。坐电车过去的话——

AI 佑芽：跑过去！

千奈：为什么要跑过去呢？

AI 佑芽：因为这样从出发的时候就已经在玩了！
早上跑步，中午去游乐园，晚上再一起吃饭团。一天可以做三件开心的事！

千奈：……的确很像花海同学会制定的计划呢。

千奈：可是，筱泽同学和我，大概还没有走到游乐园就动不了了。

AI 佑芽：没关系！到时候我背着千奈酱，再抱着广酱继续跑！

千奈：两个人一起吗？

AI 佑芽：还没有试过，所以正好可以试试看！
```

这段对话已经确定为正式开场的核心案例。“像”由推理方式表现出来：

- 佑芽行动优先、元气直接；
- 遇到困难时，她首先想到用自己的体力直接解决；
- 她没有先细致考虑千奈和广是否愿意被带着跑；
- 跑步、游乐园和饭团自然被合并成同一个计划；
- 模型能够根据千奈的回答继续聊，而不是输出一段预制人物介绍。

不要由旁白直接宣布“模型模仿得非常逼真”。让千奈的反应和真正佑芽随后受到的惊吓证明这一点。

### 真正的佑芽登场

```text
佑芽：广同学，千奈同学，你们在看什么？

千奈：我正在和佑芽同学商量周末去哪里玩。

佑芽：可是我刚刚才过来啊？……跑去游乐园，听起来很不错！
```

千奈把电脑转过去。佑芽发现刚才一直是 AI 在扮演自己。

她读完聊天记录以后提出：

```text
佑芽：AI 酱刚入学的时候，明明还会把美铃同学和毛球弄混，
还说“毛球是孤高的狼，从不贪嘴”……
怎么现在已经这么聪明了？
```

“刚入学”是把游戏于 2024 年 5 月 16 日开服写成校内时间的玩笑。

“美铃与毛球”的具体错误按使用者提供的设定处理；正式落稿前，不额外补写未经确认的原作事实。

### 三个人最初的讨论

这里可以有一小段真正的日常讨论，不要马上进入公式。

千奈和佑芽可以依次提出普通使用者最容易想到的原因：

- AI 读过的资料更多了；
- 电脑变快了；
- 模型变大了；
- 人类更会教它说话了；
- 也许这些原因同时存在。

广承认“AI 为什么变聪明”包含很多问题，不可能在一次小课堂中完整回答。

她随后选择一个最适合从公开实现中检查的入口：

> 先看模型本身变成了什么样。

## 二、问题收束：从“AI 变聪明”到“GPT-2 与 Kimi K3”

广打开两个公开、可以观察其结构的模型：

- 2019 年的 GPT-2；
- 2026 年的 Kimi K3。

她选择这两个模型，不是声称它们代表 AI 发展的全部历史，而是因为：

1. 时间上形成清楚的两端；
2. 都能观察实际架构与实现；
3. GPT-2 保留了现代 decoder-only 模型的基本骨架；
4. Kimi K3 展示了七年后规模和架构同时变化到什么程度。

### 比较的核心问题

参数规模的增长只作为背景事实简述，不列出倍率，也不让它承担引子的功能。广选择 GPT-2 与 Kimi K3，是为了观察七年间模型主干发生了哪些变化。

正文的问题直接写成：

> 从 GPT-2 到 Kimi K3，哪些基本结构仍然存在，哪些地方已经换了做法？

至此，日常引子结束。广接过叙述，用第一人称开始讲述：

> 我想从 GPT-2 开始。它已经具备今天仍然熟悉的基本外形，也足够简单，适合作为这次比较的起点。

这不是宣布要“拆解 GPT-2”，而是自然进入 `From GPT2 to Kimi3, Explained` 的第一个原文章节。

## 三、正文主体：由广第一人称按照原文章节讲述

正文保持原文顺序，不重新组织成百科简史，也不把每一节改造成“提问—失败—解答”的课堂机关。

广的第一人称主要承担四种叙述动作：

1. 说明自己此刻观察的是模型的哪一部分；
2. 用自然语言解释原文中的代码、公式或结构图在做什么；
3. 说清这种设计相对上一种设计改变了什么；
4. 在必要处承认自己的疑惑、理解过程和取舍判断。

代码、公式和图示仍按原文需要保留，但不逐行拆解，也不让千奈、佑芽轮流代替读者提问。

### 第一节：GPT-2——我选择的起点

#### 第一人称入口

广先说明为什么从 GPT-2 开始：它不是最早的语言模型，但现代 decoder-only Transformer 的基本形状已经清楚，而且公开实现足够简洁，适合作为比较的起点。

#### 要讲的内容

- decoder-only 架构；
- token embedding 与 position embedding；
- Transformer block：注意力层、MLP、残差连接和 LayerNorm；
- Q、K、V 与 causal self-attention；
- 最终 hidden state 如何映射到词表 logits；
- 自回归生成时只消费最后一个位置的 logits；
- 不缓存时会重复计算此前 token；
- KV Cache 怎样避免重复计算；
- KV Cache 又怎样随序列长度增长；
- GPT-2 基线约 1.24 亿参数。

#### 叙述落点

广讲到 KV Cache 时，不把它写成突发难题，而是平静指出：缓存免去了重复计算，却会随着上下文一起增长。原文由此进入线性注意力；正文照着这个自然转折继续。

---

### 第二节：线性注意力——把增长的历史折叠成固定状态

#### 第一人称入口

广从自己阅读线性注意力论文时的困惑写起：论文所说的 `O(N^2)` 究竟指什么，为什么不能直接用今天对 FlashAttention 和 KV Cache 的理解去读一篇 2020 年的论文。这个时间差可以保留，因为它让广的讲述像真实阅读记录，而不是全知讲义。

#### 要讲的内容

- Softmax 注意力先计算 `q·k` 再施加非线性；
- 为什么每个 Query 与每个 Key 发生耦合；
- 线性注意力分别对 Q、K 做特征映射；
- 乘法重新结合以后，可以把历史折叠进固定大小的 `D×D` 状态；
- 从 KV Cache 的 `O(N)` 增长转向固定状态；
- `ELU+1` 与 Softmax kernel 的表达能力差异；
- 线性注意力仍然包含非负化、归一化和 Value 加权平均三个基本步骤。

#### 必须保留的取舍

固定状态更省空间，但它不再为每一个早期 token 保存完全独立的表示。

#### 叙述落点

广明确这项交换：不再保留不断增长的独立 K、V，换来固定状态；代价是早期信息不再拥有彼此分离的槽位。接着进入原文的 DeltaNet。

---

### 第三节：DeltaNet——不只是继续添加，而是修改旧关联

#### 第一人称入口

广把固定状态写成一块会被反复写入的关联记忆。她不另造贯穿全文的生活比喻，只用一次简短说明帮助读者理解：持续相加很省空间，但写得越多，旧关联越容易被覆盖和混合。

#### 要讲的内容

- 固定容量状态为什么会发生容量过载；
- 纯加法写入为什么不能删除旧关联；
- Key 归一化后怎样精确读回对应 Value；
- Delta Rule 先读出旧值，再计算新旧值的差；
- `beta` 怎样控制逐 token 写入强度；
- 状态更新怎样从“添加一条新关联”变成“修正已有关系”。

关键代码与公式只保留能解释以下三步的部分：

```text
读出旧值
→ 计算差值
→ 把差值写回
```

#### 叙述落点

这一节最终说明的是：Delta Rule 不再只是把新内容加进去，而是先看原位置有什么，再写入真正需要改变的部分。随后按原文进入它的并行实现。

---

### 第四节：DeltaNet 的分块并行——递归怎样进入矩阵计算

这一节来自原文，但在本章中压缩处理。广只说明逐 token 递归为什么不利于长序列训练，以及分块以后哪些计算留在块内、哪些状态在块之间传递。

#### 要讲的内容

- 朴素 Delta Rule prefill 为什么需要逐 token 顺序执行；
- chunk 怎样把序列分块；
- chunk 内计算普通的带掩码注意力；
- chunk 之间传递最终状态；
- `C=N` 退化为全注意力，`C=1` 接近普通线性递归；
- 中间的 `C` 在并行计算和额外 FLOPs 之间取平衡；
- Delta 更新为什么还需要重新参数化，才能一次处理一个 chunk 内的修正量。

#### 压缩处理

- `C=64/128` 只作为实践取值简述；
- Tensor Core、UMMA 和 kernel 细节放脚注或删除；
- 不展开完整向量化 forward substitution 的逐行代码；
- 保留一张分块图和一份简化伪代码即可。

#### 叙述落点

本节不讨论部署，不展开 GPU 喜欢什么矩阵粒度，也不评价 kernel 性能。它只负责让读者知道：Delta Rule 可以经过重新参数化，以分块方式执行。完成这个必要交代后，广继续讲 Gated DeltaNet。

---

### 第五节：Gated DeltaNet——给有限状态加入遗忘

#### 第一人称入口

广沿用原文的区分：Delta Rule 擅长在有新内容时改写某条关联，却不等于能够在上下文切换后主动释放整块旧状态。这里开始讨论“遗忘”，但不把它写成角色格言。

#### 要讲的内容

- Delta Rule 只能在有明确替代内容时更新旧关联；
- 上下文切换时，需要让旧状态整体衰减；
- Mamba 式 `alpha` 门如何控制旧状态保留比例；
- 统一衰减会让重要和不重要的关联一起变淡；
- Gated Delta Rule 怎样结合精确更新和状态衰减；
- 累计衰减可以怎样理解成乘法意义上的前缀积。

#### 叙述落点

广说明 Gated DeltaNet 把精确修改与整体衰减放在同一个更新式里，然后自然转到 KDA 对衰减粒度的进一步改变。

---

### 第六节：KDA / Kimi Linear——更细粒度地分配记忆容量

#### 第一人称入口

到这里，广第一次真正抵达 Kimi 的架构。她回顾前面的 Delta Rule 和门控，只为说明 KDA 把单一衰减值推进为逐通道控制；不再回头重复完整推导。

#### 要讲的内容

- KDA 把标量衰减扩展为逐通道衰减；
- `alpha` projection 提供更细粒度的容量控制；
- Kimi Linear 交错使用 KDA 与 MLA；
- MLP 被 MoE 替代；
- 新增容量不是无目的堆叠，而是被放进衰减控制、选择性检索和专家计算等具体位置；
- 在受控对比中，Kimi Linear 对全注意力提出的质量与效率主张。

#### 叙述落点

广在这里第一次明确回应开场的问题：Kimi Linear 不是原样复制 GPT-2，而是把容量用于逐通道衰减、混合注意力和稀疏专家等具体结构。这个回应由广直接叙述。

---

### 第七节：Kimi K3——这些机制怎样组合到一起

#### 第一人称入口

广把 Kimi K3 视为前文机制的组合结果，而不是再开一份独立的模型规格清单。她先给出宏循环的总体结构，再分别说明 KDA、MLA、MoE 与 AttnRes 在其中所处的位置。

#### 要讲的内容

- 23 个四层 macrocycle；
- 每个 macrocycle 前三层使用 KDA，第四层使用 MLA；
- 第一层为稠密前馈网络，其余层使用潜空间 MoE；
- Gated MLA；
- MLA Query LoRA 与输出门控；
- 潜空间 MoE；
- SiTU 激活函数；
- 每 12 层一次的 blockwise AttnRes。

#### 详略安排

正文重点放在：

- KDA 与 MLA 为什么交错；
- 固定状态递归记忆与完整 Softmax 检索为什么需要同时存在；
- MoE 怎样把更大参数量变成稀疏、按需使用的计算容量；
- AttnRes 为什么从模型深度方向补充选择性检索。

以下内容只简述：

- 898 个专家的完整数量配置；
- SiTU 的逐行代码；
- kernel 未融合时的具体性能开销；
- 部署吞吐量与延迟数字。

这些数据可以留在图注、脚注或附录，不占据人物课堂的主体。

---

### 第八节：AttnRes——不再平等对待每一层输出

#### 第一人称入口

广把观察方向从 token 序列转向模型深度：前面讨论的是怎样从上下文中保存和取回信息，这一节讨论的是深层网络怎样重新选择较早的层表示。

#### 要讲的内容

- 普通残差流怎样逐层累加；
- 越深的层为什么面对越来越混合的表示；
- AttnRes 怎样为较早的层输出学习不同权重；
- Query–Key 点积怎样选择更有用的深度表示；
- blockwise AttnRes 为什么只在固定边界执行；
- MLA 与 AttnRes 的区别：一个从 token 上下文检索，一个从早期深度表示检索。

#### 本节功能

完成原文最后一块拼图，并为结论准备三个动词：

```text
保存什么
怎样更新
从哪里重新检索
```

## 五、结尾：回到“AI 为什么变聪明”

### 回到最初的问题

技术讲解结束时，仍由广以第一人称回答开场的问题，不把总结拆给千奈和佑芽：

```text
从 GPT-2 到 Kimi K3，模型的规模扩大了；与此同时，保存状态、更新状态、
控制旧信息衰减，以及重新检索上下文和早期表示的方式也发生了变化。
```

### 不把一个架构解释冒充成全部答案

开场问的是“AI 为什么聪明了这么多”，正文检查的是其中一个重要部分：模型规模与主干架构。

结尾应主动说明，本章没有完整讨论：

- 训练数据怎样变化；
- 训练计算量怎样增长；
- 指令微调和后训练怎样让模型更会回答；
- 角色资料怎样进入上下文；
- 产品侧提示词、检索与安全机制怎样影响最终聊天。

这些同样会影响开场那段“AI 佑芽”。因此广明确说明：本章回答的是模型主干发生了什么变化，而不是宣称角色扮演能力来自某一个单独结构。

可用第一人称表述：

> 我在这里能够确认的，是模型规模和主干架构发生了怎样的变化。至于它为什么能把佑芽扮演得这么像，数据、训练与后训练仍然是没有展开的部分。

### 生活化回收

广结束讲述后，把视线移回仍然开着的聊天窗口。AI 佑芽还在安排去游乐园的路线，真正的佑芽则开始认真讨论几点出发、要不要把咲季也叫上。

这里不再制造一个“AI 又答错了”的反转。开场已经证明它进步得足够明显；结尾只让真实对话继续发生。广在第一人称中意识到，自己解释了模型内部的一部分变化，却没有穷尽“聪明”这个问题。

收尾的情绪不是宣布 AI 仍然很笨，也不是赞叹技术万能，而是：这次比较已经有了答案，同时还留下了下一次可以继续观察的部分。

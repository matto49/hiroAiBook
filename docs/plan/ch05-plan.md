# ch05 改稿计划：世界模型、VLA 与 sim2real 试错课

## 本章新定位

`ch05` 承接 `ch04` 的失败地图，不再从概念名词直接开讲，而是从试作机零号的日志开始：它能移动、能避开一部分障碍、能推近水瓶，但遇到新光照、新摆放、新服装、新指令时依然会犯很笨的错。

定稿设定：

- 小机器人仍然是 `ch04` 的低成本小车迭代版，不突然升级成人形或昂贵平台。
- Alice 服装梗保留，并明确变成“服装变化 / 外观分布变化”的视觉泛化测试，也方便后续插画。
- 前沿路线单独做半章技术速览，形式是两人在休息时翻资料、聊天、挑选“哪些技术能让小机器人不那么笨拙”。
- 本章结尾让小机器人完成一次笨拙但真实的送水，作为 `ch06` 后日谈的接口。

本章的重点是“让小机器人少犯同一种错”：

- 世界模型：让系统在内部预演“如果这样动，接下来会发生什么”。
- VLA：把视觉、语言和动作接起来，让它从“听懂任务”走向“输出动作块”。
- sim2real：先在仿真练习室里大量试错，再回到真实练习室做小步校准。
- 前沿路线：单独做半章技术速览，但每条路线都回答“能帮零号机改哪里”。

章节气质应是两个人一起聊天、回放日志、改设置、试错。理论要有，但每个理论点都尽量对应一次小实验。

## 正文结构建议

### 1. 从失败日志开始

开头不要写“世界模型是……”，而先列出三条 `ch04` 产生的失败：

- 视觉失败：光照变化、服装变化、遮挡导致认错。
- 动作失败：仿真里能走，真实地板上偏航。
- 指令失败：听懂“拿水”，但不知道先绕开椅子还是先找桌边。

然后提出本章问题：

```text
只会反应不够。
它需要先预测一点，理解一点，再动一点。
```

### 2. 世界模型：给试作机一间脑内练习室

技术目标：讲清世界模型不是“把未来视频画漂亮”，而是给规划和训练提供可用的未来表征。

建议公式保留：

```tex
z_t = e_\theta(o_t), \qquad
\hat{z}_{t+1}=f_\theta(z_t,a_t)
```

讲解方式：

- `o_t` 是当前观察：摄像头画面、位置、障碍物。
- `z_t` 是压缩后的“当前情况”。
- `f` 尝试预测：如果下一步左转，会不会撞到椅子。

初星学园比喻：

- 世界模型像排练前的“脑内走位”，但不是幻想舞台，而是带约束的预演。
- 如果広在舞台上预判三拍后的站位，试作机也要预判三步后的障碍。

需要修正当前正文：

- 不写“世界模型一开始是李飞飞提出的”这种容易失真的说法。
- 可以改成：世界模型来自模型化环境动力学、模型预测控制、模型式强化学习等更长的传统，在深度学习和视频基础模型阶段获得了新的表达方式。

### 3. 世界模型在本章里的三种用法

直接绑定小机器人。

1. **预演动作。**  
   在内部 rollout 几步，选择不撞椅子的路线。
2. **制造失败样本。**  
   在仿真中生成不同灯光、不同椅子位置、不同服装遮挡。
3. **辅助训练表征。**  
   让系统学习“下一秒应该仍然是同一个杯子 / 同一条路”，减少一换角度就失忆。

对应小剧场道具：

- 服装架用于遮挡。
- Alice 服装用于视觉泛化。
- 地板胶带用于定位与评测。

### 4. VLA：从“听懂”到“出手”

技术目标：把 VLA 讲成试作机执行自然语言任务的接口。

建议公式：

```tex
p_\theta(a_{t:t+K-1}\mid o_{1:t}, q, s_t)
```

解释：

- `q` 是 Producer 的指令：“把水送到蓝色胶带旁边”。
- `o` 是机器人看到的画面和历史。
- `s` 可以是来自定位、世界模型或任务状态的内部状态。
- 输出不是一条文字答案，而是一小段动作 `action chunk`。

章节写法：

- 先让试作机把“把水送到広那里”误解成“向広移动”，差点越过安全线。
- Producer 增加边界：只能送到胶带旁，不接近人脚。
- 広指出：语言理解必须和可供性、安全距离、动作能力一起绑定。

### 5. sim2real：练习室和仿真器之间的缝

本节要成为 `ch05` 的实践核心。

建议流程：

1. **收集真机日志。**  
   `ch04` 的失败地图、相机画面、里程计、急停记录。
2. **搭一个仿真练习室。**  
   只保留与任务相关的门、桌、椅、胶带、服装架。
3. **随机化。**  
   灯光、摩擦、轮子噪声、椅子位置、目标外观、延迟。
4. **训练 / 微调。**  
   世界模型负责预演，VLA / 技能策略负责动作输出。
5. **真机小步回放。**  
   每次只放开一点动作，保留急停和低速。
6. **记录差异。**  
   仿真没覆盖到的现实误差，回流到下一轮随机化。

可用一句核心解释：

```text
sim2real 不是把仿真做得和现实完全一样。
更常见的思路，是让仿真故意变得很多样，使真实世界落在它见过的范围里。
```

### 7. 三轮优化实验

让前沿概念落地到剧情。

#### 第一轮：服装变化导致认错

- Alice 服装让试作机把広识别成“未知目标”。
- 技术点：开放词汇视觉、身份 / 目标表征、分布外外观。
- 修正：不要让任务绑定“衣服特征”，而要绑定目标位置、语音确认、Producer 指令和安全边界。

#### 第二轮：仿真成功，真机偏航

- 仿真里路线完美，真实练习室地板摩擦不同，小车偏到椅子旁。
- 技术点：sim2real gap、动力学随机化、轮速噪声。
- 修正：随机摩擦、延迟、轮径误差；部署时低速闭环。

#### 第三轮：听懂指令，但动作太贪心

- VLA 产生的动作块太长，局部避障来不及接管。
- 技术点：action chunk 长度、安全层、分层控制。
- 修正：缩短动作块，加入急停和局部规划器，复杂任务拆成子任务。

每轮都用“现象 -> 技术拆解 -> 修改 -> 再试”的节奏，避免纯问答说教。

### 8. 结尾：已经不是零

结尾落在一次不完美成功：

- 试作机把水慢慢送到広身边的安全胶带边。
- 它绕远，停顿，动作很不漂亮。
- Producer 没有夸大成功，只记录“可复现一次，待验证”。
- 広看得很认真，给出安静结论。

可用结尾方向：

```text
広：很慢。很笨。也不稳定。
P：这算成功吗？
広：算开始。
広：已经不是零了。
```

## 对白节奏原则

広：

- 她不是前沿论文播报员，而是在看一个笨拙系统如何“学会继续”。
- 她对试作机可以更温柔一点，因为它出错的方式很像“不适合但还在试”。
- 仍然要短句、轻停顿、先观察再结论。

Producer：

- 负责把测试收束成可执行步骤。
- 负责安全：低速、急停、离人距离、不让広亲自追着机器人跑。
- 可以被卷进去，但不能只当吐槽役。

避免：

- 连续堆“截至某年某月，某公司发布……”。
- 把世界模型讲成“会想象所以万能”。
- 把 VLA 讲成“一个模型解决机器人学”。
- 把 sim2real 写成“仿真练一练就能上真机”。

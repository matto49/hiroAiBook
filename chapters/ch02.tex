\section{GPT-2}

GPT-2 是一张容易摊开的底图：decoder-only Transformer 的主干已经成形，结构又没有复杂到遮住它。等走到 Kimi K3，再看哪些东西留了下来，哪些被换掉。\cite{waterloo-worklog,gpt2}

先跟着一串 token 往前走。词嵌入把 token 变成向量，位置嵌入标出它们在序列中的位置；两者相加后，依次进入多层 Transformer block。最后，LayerNorm 整理隐藏状态，语言模型头把它投影回词表，为每个候选 token 给出一个分数，也就是 logits。下面几行代码，就是这条主干的完整路径。

\begin{lstlisting}[language=Python,caption={GPT-2 主干前向传播}]
tok_emb = self.transformer.wte(idx)       # (B, T, C)
pos_emb = self.transformer.wpe(pos)       # (T, C)
x = self.transformer.drop(tok_emb + pos_emb)
for block in self.transformer.h:
    x = block(x)
x = self.transformer.ln_f(x)
logits = self.lm_head(x)
return logits
\end{lstlisting}

循环里的工作都发生在 block 中。每个 block 只反复做两件事：先用因果自注意力交换位置之间的信息，再用 MLP 逐位置变换。两次计算前都先做 LayerNorm，结果则通过残差连接加回原表示。

\begin{lstlisting}[language=Python,caption={带注意力与 MLP 的 Transformer block}]
class Block(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.ln_1 = LayerNorm(config.n_embd)
        self.attn = CausalSelfAttention(config)
        self.ln_2 = LayerNorm(config.n_embd)
        self.mlp = MLP(config)

    def forward(self, x):
        x = x + self.attn(self.ln_1(x))
        x = x + self.mlp(self.ln_2(x))
        return x
\end{lstlisting}

把注意力再展开一层，输入会被投影成 Query、Key 和 Value。当前位置的 Query 与前文的 Key 逐一比较；匹配越高，对应的 Value 就越多地进入输出。因果掩码挡住尚未生成的未来，Softmax 再把这些匹配分数归一化。

\[
\operatorname{Attn}(Q,K,V)
=
\operatorname{softmax}\left(
\frac{QK^{\mathsf T}}{\sqrt{d}}
+M_{\mathrm{causal}}
\right)V
\]

把这条路径放回刚才的聊天窗口，屏幕上的回答不会一次写完。提示词、人物说明和已经生成的回复先变成 token；模型给下一步的所有候选项打分，选出一个，再把它接回输入。那句“下车以后再跑”，也是这样一个 token、一个 token 长出来的。

假设模型正在生成“跑”附近的内容，新的 Query 可能与前文中“游乐园”“坐电车”等位置的 Key 得到较高匹配，相应的 Value 便更多地进入当前表示。这只是注意力可能走过的一条路径；模型里没有一条人工规则写着“佑芽必须选择跑步”。人物说明和前文词语会在一层层运算中改变候选 token 的概率，最后才落到屏幕上的选择。

这里要把一次生成拆成两个时期。整段提示词第一次进入模型时，会有许多 token 一起计算，这叫 \textit{prefill}；随后进入 \textit{decode}，每一步只新增一个 token，却仍要读取此前的历史。Prefill 关心的是怎样并行处理已经到齐的输入，decode 则要避免每一步都重算过去。

Decode 真正拿去采样的，只有最后一个位置的 logits。如果每走一步都把整段前文重算一遍，早期 token 的 Key 和 Value 就会反复投影。KV Cache 省下这部分工作：已经算过的 Key、Value 留在缓存中，下一步只计算新 token 的一份，再接到后面。

\begin{lstlisting}[language=Python,caption={带 KV Cache 的 Softmax 注意力核心}]
q, k, v = split_heads(self.qkv_proj(x))

if past_kv is not None:
    k_past, v_past = past_kv
    k = torch.cat((k_past, k), dim=2)
    v = torch.cat((v_past, v), dim=2)

scores = (q @ k.transpose(-1, -2)) / math.sqrt(d_head)
if past_kv is None:
    scores = scores.masked_fill(causal_mask, float("-inf"))

attn = scores.softmax(dim=-1)
out = attn @ v
return self.o_proj(merge_heads(out)), (k, v)
\end{lstlisting}

重复计算少了，缓存却没有变小。前文每增加一个 token，其中就多出一对 Key、Value；上下文越长，这份历史也越长。GPT-2 留下的问题因此很具体：能不能不再逐 token 保存整段历史？

\section{线性记忆}

这篇 2020 年论文对复杂度的描述，放到今天很容易和 KV Cache、FlashAttention 混在一起。三者解决的并不是同一件事：KV Cache 避免重复投影，但缓存和每步读取的历史仍随序列增长；FlashAttention 改善精确注意力的显存读写与中间存储，却没有消除二次算术量。线性注意力要做得更彻底——连历史的保存形式和乘法顺序一起改变。\cite{linear-transformer}

Softmax 注意力要先计算每一对 Query 与 Key 的分数，再施加指数和归一化。非线性卡在两个乘法之间，运算不能重新结合。线性注意力先分别映射 Query 和 Key：

\[
\phi(q)=\operatorname{ELU}(q)+1,\qquad
\phi(k)=\operatorname{ELU}(k)+1.
\]

这样，历史就能先合并进固定大小的状态

\[
S_t=\sum_{i=1}^{t}\phi(k_i)^{\mathsf T}v_i,
\qquad
z_t=\sum_{i=1}^{t}\phi(k_i),
\]

当前 Query 再从中读取：

\[
o_t=
\frac{\phi(q_t)S_t}
     {\phi(q_t)z_t}.
\]

空间是在乘法次序改变以后省下来的。Softmax 注意力先列出当前位置与所有历史位置之间的分数；这里则先计算 $\phi(k_i)^{\mathsf T}v_i$，把过去折叠进矩阵，再用 $\phi(q_t)$ 读取。只要 head 维度不变，$S_t$ 与 $z_t$ 的尺寸就固定。前文从一百个 token 增加到一万个，decode 携带的仍是同样大小的状态。

$\operatorname{ELU}+1$ 并不等同于 Softmax。它选择的是一种可以拆开计算的非负特征映射，仍然经过非负化、归一化和 Value 加权平均，但表达能力与原来的 Softmax kernel 不同。

\begin{lstlisting}[language=Python,caption={把历史 K、V 折叠进固定状态}]
q, k, v = split_heads(self.qkv_proj(x))
q = F.elu(q) + 1
k = F.elu(k) + 1

S, z = cache if cache is not None else (0.0, 0.0)
S = S + k.transpose(-1, -2) @ v
z = z + k.sum(dim=-2, keepdim=True)

out = q @ S
denom = q @ z.transpose(-1, -2)
out = out / denom.clamp_min(1e-6)
return self.o_proj(merge_heads(out)), (S, z)
\end{lstlisting}

固定状态没有凭空消除历史的体积，而是把许多位置压进了同一个矩阵。KV Cache 仍为每个早期 token 留着独立的 Key 和 Value；$S_t$ 只有有限的槽位。写入越来越多时，早期信息不再彼此分开，也就可能相互干扰。代价很明确：省下随序列增长的空间，交出逐 token 保存历史的保真度。

刚才“毛球”的错误可以暂时缩成一个低维例子：旧材料沿某个 Key 方向写入“孤高、不贪嘴”，新材料又沿相近方向写入“其实很贪吃”。纯加法只会把两个 Value 叠在一起。Query 再指向这里时，读到的可能是混合物，而不是后来的修正。

真实模型里没有一个写着“毛球”的格子。Key、Value 和通道都是训练得到的连续向量；这个例子只保留了冲突的部分——方向越接近，写入越容易彼此影响。一旦放弃逐 token 的独立槽位，怎样改掉旧关联就成了下一个问题。

固定状态的纯加法可以写成：

\[
S_t=S_{t-1}+k_t^{\mathsf T}v_t,
\]

Delta Rule 改的正是这个写入动作：它先用当前 Key 读取旧值，再只写回旧值与目标之间的差。\cite{fast-weight}

\begin{lstlisting}[language=Python,caption={带逐 token 写入强度的 Delta 更新}]
q, k, v = split_heads(self.qkv_proj(x))
q = F.normalize(F.silu(q), dim=-1)
k = F.normalize(F.silu(k), dim=-1)
beta = torch.sigmoid(self.w_beta(x)).view(B, 1, T, 1)

S = cache if cache is not None else 0.0
v_old = k @ S
u = beta * (v - v_old)
S = S + k.transpose(-1, -2) @ u

out = q @ S
return self.o_proj(merge_heads(out)), S
\end{lstlisting}

这里的 $\beta$ 控制写入强度。Key 归一化后，用同一个 Key 从 $k^{\mathsf T}v$ 中读取，得到的就是 $v$。因此，$v-v_{\mathrm{old}}$ 不是又一份完整内容，而是旧值距离目标还差的部分。

从同一个 Key 方向把更新式再读一次，效果会更清楚。记 $v_{\mathrm{old}}=k_tS_{t-1}$，并令 $\lVert k_t\rVert=1$，则

\[
k_tS_t=(1-\beta_t)v_{\mathrm{old}}+\beta_t v_t.
\]

$\beta_t=0$ 时，原关联不动；$\beta_t=1$ 时，当前 Key 方向的读出被推向新 Value；取中间值时，两者平滑过渡。这个结论来自单位 Key 的简化推导，相近方向的其他关联仍可能受到影响。纯加法总在问“再加多少”，Delta Rule 先问“旧值离目标还有多远”。

固定状态现在不只会累加，也能修正已经找到的关联。不过，更新仍依赖前一步状态。按 token 顺序写出来很简单：

\begin{lstlisting}[language=Python,caption={顺序执行的 Delta 更新}]
S = torch.zeros(B, H, D, D) if cache is None else cache
outs = []
for i in range(T):
    k_i = k[:, :, i:i+1]
    v_i = v[:, :, i:i+1]
    b_i = beta[:, :, i:i+1]
    v_old = k_i @ S
    u_i = b_i * (v_i - v_old)
    S = S + k_i.transpose(-1, -2) @ u_i
    outs.append(q[:, :, i:i+1] @ S)
out = torch.cat(outs, dim=2)
\end{lstlisting}

顺序循环在 decode 中没有额外制造等待——下一个 token 本来就要等上一个生成。训练和 prefill 不同：整段输入已经摆在面前，若第 $i+1$ 个位置仍必须等第 $i$ 个位置写完状态，矩阵硬件就只能跟着逐步排队。

解决办法是把序列切成 chunk。块内位置已经全部可见，可以用因果掩码一起计算；块与块之间只传递压缩后的最终状态。因此，一个块的输出有两个来源：进入该块以前积累的状态，以及本块中更早位置刚写下的内容。

\begin{lstlisting}[language=Python,caption={重参数化后的 chunk Delta 核心}]
Q, K, V = map(lambda x: x.reshape(-1, C, D), (Q, K, V))
beta = beta.reshape(-1, C)
K_beta = K * beta.unsqueeze(-1)
V_beta = V * beta.unsqueeze(-1)

Tmat = -(K_beta @ K.transpose(-1, -2)).tril(-1)
for i in range(1, C):
    Tmat[:, i, :i] += (
        Tmat[:, i, :, None] * Tmat[:, :, :i]
    ).sum(-2)
Tmat = Tmat + torch.eye(C, device=K.device)
W, U = Tmat @ K_beta, Tmat @ V_beta

for q_i, k_i, w_i, u0_i in zip(Q, K, W, U):
    u_i = u0_i - w_i @ S
    out_inter = q_i @ S
    out_intra = (q_i @ k_i.T).tril() @ u_i
    S = S + k_i.T @ u_i
    outs.append(out_inter + out_intra)
\end{lstlisting}

chunk 覆盖整个序列时，所有交互都落入块内，计算形态重新变成二次复杂度；但 Delta 修正仍然存在，并不等同于标准 Softmax 注意力。chunk 缩到一个 token 时，则回到完全递归。中间取值是在块内并行和块间递归之间选择落点。

图中的两项对应代码的两个输出：$\texttt{out\_inter}=Q_iS_{i-1}$ 读取块前状态，$\texttt{out\_intra}$ 则用带因果掩码的 $Q_iK_i^{\mathsf T}$ 读取块内较早位置。它们相加，才得到当前块的输出。

chunk 表示计算粒度，不是记忆窗口。块结束后，信息仍会写进状态并交给下一块；改变的只是每次能并行展开多少更新，以及多少块边界必须顺序经过。

Delta Rule 的麻烦在于，每次修正都要先知道“写入前读到了什么”。论文借助广义 Householder 转移矩阵重新参数化，把块内连续的修正量整理成可以一并计算的矩阵。结果是，状态继续在块间递归，块内计算却可以交给矩阵运算。

\section{门控}

Delta Rule 能修正某个 Key 指向的关联，前提是新内容正好来到了这个位置。话题整体切换时，许多旧关联未必都有对应的新值，却仍占着有限状态。此时需要的不是逐条改写，而是让过去自行淡出。

门控为旧状态乘上保留比例 $\alpha_t$。\cite{gated-delta}

\[
S_t=
\alpha_t S_{t-1}
+k_t^{\mathsf T}
\left[\beta_t\left(v_t-k_tS_{t-1}\right)\right],
\qquad 0\leq\alpha_t\leq1.
\]

\begin{lstlisting}[language=Python,caption={门控与 Delta Rule 的组合}]
S_old = cache
v_old = k @ S_old
u = beta * (v - v_old)
S = alpha * S_old + k.transpose(-1, -2) @ u
\end{lstlisting}

式子里，$\beta_t$ 只管当前 Key 指向的关联，要把它朝新 Value 修正多少；$\alpha_t$ 则先作用于整个旧状态，决定过去还留下多少。前者修改一个位置，后者释放整片容量。两种动作发生在同一次更新中。

$\alpha_t=1$ 时，旧状态完整保留；它越接近零，过去衰减得越快。一项信息从写入到再次被读取，中间会连续乘过所有门值。单步变化看起来很轻，许多步以后却决定了它还能留下多少。

若某项信息在第 $r$ 步写入，到第 $t$ 步仍保留的比例近似为

\[
\prod_{i=r+1}^{t}\alpha_i.
\]

连续一百步都取 $\alpha=0.99$，保留量约为 $0.366$；若取 $0.999$，则仍约为 $0.905$。门值因此不是“记住”与“忘掉”之间的一次选择，而是在给状态安排不同的寿命。

Gated DeltaNet 既能定点改写，也能整体衰减。不过，它在每个 token、每个 head 上的 $\alpha_t$ 仍是一个标量：同一时间步里，该 head 的所有状态通道按同一比例变淡。Kimi Delta Attention（KDA）继续拆开这只门，让各通道拥有自己的衰减速度。\cite{kimi-linear}

\[
\boldsymbol{\alpha}_t
=\sigma(W_\alpha x_t),
\qquad
S_t=
\operatorname{diag}(\boldsymbol{\alpha}_t)S_{t-1}
+\Delta S_t.
\]

S = S + delta                            # Delta Rule

从标量到向量，代码只多了一层维度，容量的分配却变细了。某些通道可以很快腾出空间，追踪最近几个 token；另一些通道则衰减得慢，跨过更长的片段。固定状态的总容量没有增加，但它不必再用同一个时间尺度对待所有方向。

这些通道并没有预先贴上“人名”“语气”或“事实”的标签。哪一部分该短暂、哪一部分该久留，仍要由训练学出来。KDA 只是状态单元；Kimi Linear 还要把它接回完整的模型。

\section{Kimi Linear 与 Kimi K3}

\subsection{KDA 与 Kimi Linear}

逐通道门控仍改变不了固定状态的一个限制：被压缩掉的位置细节，不能只靠更精细的衰减重新找回来。因此 Kimi Linear 没有让所有层都使用 KDA，而是把它与 Multi-head Latent Attention（MLA）交错排列。多数层继续读写固定状态，周期性的 MLA 则回到 token 上下文，执行一次 Softmax 检索。

Kimi Linear 论文还报告，在受控对比中，这种混合结构的质量优于其实验中的全注意力基线，解码吞吐量最高提升 6 倍。这里的数字属于论文给定模型与硬件条件下的结果，不是所有任务上的普遍保证。\cite{kimi-linear}

\subsection{Kimi K3}

Kimi K3 把这种混合节奏扩展成整条主干。前 92 层组成 23 个四层周期，每个周期依次经过三层 KDA 和一层 Gated MLA；第 93 层再补上一层 Gated MLA。因此，官方配置合计 69 个 KDA 层和 24 个 Gated MLA 层。\cite{kimi-k3}

一个 token 走过这样的四层周期时，前三层从固定状态读取，同时把当前内容写回；第四层重新检查 token 上下文，并用输出门决定检索结果有多少进入残差流。KDA 让大多数层不必携带不断增长的 K、V 历史，MLA 则定期补回准确的位置检索。

注意力之后还有前馈计算。第 1 层使用稠密网络，其余层主要使用 LatentMoE：其中有 896 个路由专家，另有 2 个共享专家。共享专家始终参与，路由器则为每个 token 从 896 个候选中选择 16 个。因此，Kimi K3 虽有 2.8 万亿总参数，每个 token 只激活约 1040 亿参数；总容量由全部专家共同贡献，单步计算只经过其中一部分。

MLA 本身也有两处改动。Query LoRA，也就是 Query 的低秩投影，减少这一分支的参数与计算；检索结果在进入残差流前还要乘上输出门。前者压缩 Query 路径，后者决定这次完整检索究竟应该写回多少。

注意力决定从历史的哪里取信息；接着，这个 token 会进入路由器选中的专家。Kimi K3 在专家内部还换用了 SiTU 激活：输入沿最后一维分成 gate 与 up 两半，由可学习参数控制双曲正切的截断范围。

\begin{lstlisting}[language=Python,caption={SiTU 激活函数}]
d = x.shape[-1] // 2
gate = x[..., :d].to(torch.float32)
up = x[..., d:].to(torch.float32)

situ_a = (
    self.beta
    * torch.tanh(gate / self.beta)
    * torch.sigmoid(gate)
)
if self.linear_beta is not None:
    up = self.linear_beta * torch.tanh(up / self.linear_beta)
return (situ_a * up).to(x.dtype)
\end{lstlisting}

式中的 $\beta\tanh(x/\beta)$ 在零附近近似线性，输入绝对值很大时则饱和在 $\pm\beta$。常用范围里的细小变化可以继续通过，极端激活却不会无限放大。Gate 分支还要乘 sigmoid，up 分支也可以拥有独立的可学习截断。路由器决定 token 去哪几个专家，SiTU 管的是它进入专家以后怎样通过非线性。

\subsection{AttnRes}

固定状态与 MLA 处理的是序列轴上的历史。Kimi K3 还要照顾另一条轴：一个表示穿过九十多层以后，浅层留下的东西怎样送到深处。

普通残差网络不断累加此前各层的输出。用简化写法表示，第 $l$ 层看到的是

\[
h_l=h_1+\sum_{i=1}^{l-1}f_i(h_i).
\]

词形、局部位置等浅层表示，与后面形成的任务相关表示，都挤进同一条残差流。简单求和不区分当前计算更需要哪一层；网络越深，后面的层越只能从混合结果里间接恢复早期信息。

Attention Residual（AttnRes）把固定求和改为带权混合：

\nopagebreak[4]

\[
h_l=
\alpha_0h_1+
\sum_{i=1}^{l-1}\alpha_i f_i(h_i),
\qquad
\sum_i\alpha_i=1.
\]

每个子层都有一个学习得到的 pseudo-query，较早的残差表示同时充当 Key 和 Value。匹配分数沿网络深度归一化，再把早期表示按权重重新组合。于是，一个 token 可以偏向浅层留下的词法信息，另一个位置也可以更多读取中段已经整理过的特征；它们不必接受完全相同的历史层总和。

\begin{lstlisting}[language=Python,caption={blockwise AttnRes 的核心操作}]
V = torch.stack(blocks + [partial_block])  # [N+1,B,T,D]
K = norm(V)
logits = torch.einsum(
    "d,nbtd->nbt", proj.weight.squeeze(), K)
h = torch.einsum(
    "nbt,nbtd->btd", logits.softmax(0), V)
return h
\end{lstlisting}

若每一层都保存并检索全部早期状态，成本会再次增长。Kimi K3 每 12 层才保存一次块级表示，后面的边界从这些 block 中选择。这样得到两条方向不同的回看路径：MLA 沿序列轴寻找较早的 token，AttnRes 沿深度轴寻找较早的 block。前者补回固定状态压掉的位置细节，后者补回深层残差冲淡的中间表示。

GPT-2 留下的是 decoder-only 的骨架；Kimi K3 重做的，是历史在这副骨架里怎样被保存和取回。固定状态负责压缩，MLA 与 AttnRes 分别从序列和深度补回细节，MoE 则把参数容量按 token 分配。

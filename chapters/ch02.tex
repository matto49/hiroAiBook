\section{GPT-2}

对话框中的 AI 佑芽，看起来像是一口气相应了一整句话，但是模型内部却没有“一口气”这回事。它每次只往前走一小步：读取已经出现的文字，给接下来可能出现的文字片段打分，选出权重最高的那个接到末尾，然后再重复执行下一步。一句完整的回答，是每次生成一点点续出来的。

 这种只根据前文一步步续写的方式，叫作自回归生成。GPT-2 是 OpenAI 在 2019 年发布的语言模型，也是 GPT 系列的第二代。它采用纯解码器 Transformer：输入只有已经出现的文字，模型不能偷看后文，只能沿着前文继续预测。GPT-2 虽然是7年前的老模型，但它的结构已经具备本章后面还会反复看到的基本轮廓，公开实现也相对简洁，所以适合作为这次的起点。\cite{waterloo-worklog,gpt2}

再处理用户发起的请求时，模型会先将输入内容切成 token，它代表着模型实际读写的片段。一个 token 可能是一个字、一个词的一部分，也可能是标点；具体怎样切，由分词器决定。我们在聊天时的提示词、聊天记录和已经生成的回答，都会先被处理成这样一串 token，在推测下一个字符应该是什么的过程中，gpt-2会给清单中的候选 token 各打一个分。这些尚未归一化的分数叫作 logits，生成程序会按照解码规则选出一个最优选的 token，把它接回前文，模型再根据变长后的前文给同一张词表重新打分。

从 token 到 logits，中间要经过下面这条主干。词嵌入先回答“这是什么 token”，位置嵌入补上“它出现在第几个位置”；两者相加后进入一层层 Transformer block。最后，词表投影再把内部向量翻译成每个候选 token 的分数。

\begin{lstlisting}[language=Python,caption={GPT-2 主干前向传播}]
tok_emb = self.transformer.wte(idx)       # (B, T, C)
pos_emb = self.transformer.wpe(pos)       # (T, C)
x = self.transformer.drop(tok_emb + pos_emb)
for block in self.transformer.h:
    x = block(x)
x = self.transformer.ln_f(x)
logits = self.lm_head(x)
return logits
\end{lstlisting}

我们暂时不关心批量计算，先忽略注释里的 $B$。$T$ 表示这次读入多少个 token，$C$ 表示每个 token 用多长的向量来表示。词嵌入的形状是 $(B,T,C)$；位置嵌入没有批量维，会复用到同一批的每条序列上。后面的 block 始终接收并返回类型不变的 \texttt{x}。

\begin{lstlisting}[language=Python,caption={带注意力与 MLP 的 Transformer block}]
class Block(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.ln_1 = LayerNorm(config.n_embd)
        self.attn = CausalSelfAttention(config)
        self.ln_2 = LayerNorm(config.n_embd)
        self.mlp = MLP(config)

    def forward(self, x):
        x = x + self.attn(self.ln_1(x))
        x = x + self.mlp(self.ln_2(x))
        return x
\end{lstlisting}


被反复加工内容的是 \texttt{x = block(x)}。一个 block 里，因果自注意力毁让较后的 token 利用已经出现的前文，MLP 再逐个位置处理汇集后的特征。计算结果通过残差连接加回原表示，所以每一层做的更像是在已有理解上补一笔，而不是把整句话推倒重算。

一次注意力计算从 Query、Key 和 Value 三组投影开始。对第 $i$ 个 token 来说，它的 Query 要和当前位置以及前面各个位置的 Key 比较，再从对应的 Value 中取回信息。这个过程可以写成：

\[
\operatorname{Attn}(Q,K,V)
=
\operatorname{softmax}\left(
\frac{QK^{\mathsf T}}{\sqrt{d}}
+M_{\mathrm{causal}}
\right)V
\]

式中的 $d$ 是一个 head 的维度。除以 $\sqrt d$ 是为了缩放点积分数；$M_{\mathrm{causal}}$ 则把未来位置挡住，使第 $i$ 个 token 只能看到它自己和此前的内容。Softmax 随后把剩余分数变成权重，加权汇总对应的 Value。

Key 决定“从哪里取”，Value 决定“取回什么”，两者分工不同。多个 head 会使用各自的投影并行计算，所得结果拼接以后，再通过输出投影回到隐藏维度。这个新表示会继续经过后面的层，并最终影响词表中的候选分数。

上面的公式只是一次注意力计算。一条完整回复会反复运行公式计算：每得到一个 token，就把它接到已有序列末尾，再计算下一个。“下车以后再跑”看起来是一句话，模型实际完成的是若干次这样的续写。

模型在收到用户发送的消息后，会把提示词、人物说明和聊天记录都全部作为前置的输入，一次性并算出各层、各个位置的 Key 和 Value；这一阶段叫作 \textit{prefill}。此后进入 \textit{decode}。每一轮只多出一个 token：它经过模型各层，与此前内容计算注意力做结合，生成最后一个位置的 logits 再交给解码程序选出后续 token。新结果接回序列，下一轮继续。

由此可以看出，在一个任务中，由于前置的输入是累加的，会有大量的重复计算。如果把这些相同的计算重复做一遍，效率会很低。GPT-2 对于这个问题，有一个很重要的优化：KV Cache。它通过把各层已经算出的 Key 和 Value 储存下来，使得在下一轮 decode 时只需计算新 token 的投影，从而加快计算速度。

\begin{lstlisting}[language=Python,caption={带 KV Cache 的 Softmax 注意力核心}]
q, k, v = split_heads(self.qkv_proj(x))

if past_kv is not None:
    k_past, v_past = past_kv
    k = torch.cat((k_past, k), dim=2)
    v = torch.cat((v_past, v), dim=2)

scores = (q @ k.transpose(-1, -2)) / math.sqrt(d_head)
if past_kv is None:
    scores = scores.masked_fill(causal_mask, float("-inf"))

attn = scores.softmax(dim=-1)
out = attn @ v
return self.o_proj(merge_heads(out)), (k, v)
\end{lstlisting}

KV Cache 能够节省重复计算的成本，但是也相应增加了历史信息记录的成本。序列每增加一个 token，缓存就要增加一组 Key 和 Value；上下文越长，decode 时需要保存和读取的内容也越多。随着问题的复杂化，另一个问题随即浮现：能不能不再逐个保存这些 K、V，却仍让后面的 token 用到前文？

\section{线性注意力与固定状态}

线性注意力给出的办法是，不再为每个早期 token 保留独立的 Key 和 Value，选择对它们做压缩处理，把它们合并到一个固定大小的抽象状态中。这样缓存不会随序列长度增长，而相应的也意味着注意力的算法也会随之改变。\cite{linear-transformer}

标准注意力先计算 $QK^{\mathsf T}$，再做 Softmax。由于 Softmax 位于两次矩阵乘法之间，所以没法简单地把计算改写成 $Q(K^{\mathsf T}V)$。但是我们可以把注意力改为分别映射 Query 和 Key，例如：

\[
\phi(q)=\operatorname{ELU}(q)+1,\qquad
\phi(k)=\operatorname{ELU}(k)+1.
\]

映射后的结果为正，后续归一化也可以拆开计算。这样此前的 Key 和 Value 便能先合并为两个状态：

\[
S_t=\sum_{i=1}^{t}\phi(k_i)^{\mathsf T}v_i,
\qquad
z_t=\sum_{i=1}^{t}\phi(k_i),
\]

有了这两个状态，第 $t$ 个 Query 就可以直接计算输出：

\[
o_t=
\frac{\phi(q_t)S_t}
     {\phi(q_t)z_t}.
\]

可以把 $S_t$ 和 $z_t$ 看成两本随读取不断更新的账。$S_t$ 是内容账本：每读入一个 token，就按照它的 Key 特征，把对应的 Value 累加进去。$z_t$ 是权重账本，它只累加同一批 Key 特征，不保存 Value。

读取时，当前 Query 用 $\phi(q_t)S_t$ 从内容账本中取出与自己匹配的 Value 总量，再用 $\phi(q_t)z_t$ 算出这些内容对应的权重总量。两者相除，就能得到归一化后的输出。

因此，decode 不必继续携带此前每个 token 的 K、V，只需保留固定大小的 $S_t$ 和 $z_t$。$\operatorname{ELU}+1$ 的作用，是把 Query 和 Key 映射成非负特征，使上面的累计与归一化可以拆开计算。它产生的权重并不是 Softmax 权重，所以线性注意力不是标准注意力的等价改写。

\begin{lstlisting}[language=Python,caption={把历史 K、V 折叠进固定状态}]
q, k, v = split_heads(self.qkv_proj(x))
q = F.elu(q) + 1
k = F.elu(k) + 1

S, z = cache if cache is not None else (0.0, 0.0)
S = S + k.transpose(-1, -2) @ v
z = z + k.sum(dim=-2, keepdim=True)

out = q @ S
denom = q @ z.transpose(-1, -2)
out = out / denom.clamp_min(1e-6)
return self.o_proj(merge_heads(out)), (S, z)
\end{lstlisting}

固定状态之所以省空间，是因为它不再保留每个 token 各自的 K、V，而是把所有 Key--Value 关联累加到同一个矩阵 $S_t$ 中。但这样做也是有代价的，$S_t$ 只留下合并后的结果，看不出某一部分由哪个 token 写入，也不能按 token 把它单独删掉。

假设前文已经沿某个 Key 方向写入旧 Value，后文又用相近的 Key 写入新 Value。两次外积会修改 $S_t$ 中重叠的部分，而纯加法只会把新内容叠在旧内容上，不会判断新值是在补充旧值，还是应该替换旧值。之后再用相近的 Query 读取，输出就可能同时带有新旧 Value 的成分。随着写入继续累积，这类重叠会越来越多，固定状态也就出现容量过载。

就这样的，为了保证上下文于的快速处理，出现了一个新的问题：“怎样在不恢复逐 token 缓存的情况下，能够灵活地改写其中一条关联？”

\subsection{Delta Rule}

固定状态的纯加法可以写成：

\[
S_t=S_{t-1}+k_t^{\mathsf T}v_t,
\]

Delta Rule 改的正是这一步。它不再把新的 Value 直接加进状态，而是先用当前 Key 读出旧值，再比较旧值与目标 Value，最后只把两者的差写回去。\cite{fast-weight}

\begin{lstlisting}[language=Python,caption={带逐 token 写入强度的 Delta 更新}]
q, k, v = split_heads(self.qkv_proj(x))
q = F.normalize(F.silu(q), dim=-1)
k = F.normalize(F.silu(k), dim=-1)
beta = torch.sigmoid(self.w_beta(x)).view(B, 1, T, 1)

S = cache if cache is not None else 0.0
v_old = k @ S
u = beta * (v - v_old)
S = S + k.transpose(-1, -2) @ u

out = q @ S
return self.o_proj(merge_heads(out)), S
\end{lstlisting}

代码中的 $u$ 就是这次真正要写入的修正量，$\beta$ 控制修正的幅度。Key 经过归一化后，如果状态中只写有 $k^{\mathsf T}v$ 这一条关联，再用同一个 $k$ 读取，就能取回 $v$。因此，$v-v_{\mathrm{old}}$ 衡量的是“当前读到的内容”距离“现在想写入的内容”还有多远。

沿同一个 Key 方向读取更新后的状态，可以直接看出这次修正的结果。记 $v_{\mathrm{old}}=k_tS_{t-1}$，并令 $\lVert k_t\rVert=1$，则

\[
k_tS_t=(1-\beta_t)v_{\mathrm{old}}+\beta_t v_t.
\]

$\beta_t=0$ 时，仍然读到旧值；$\beta_t=1$ 时，这个 Key 方向会被改写成目标 Value；取中间值时，新旧内容按比例过渡。这里假设 Key 已归一化，而且只考察当前方向。实际状态中若还有相近的 Key，它们对应的关联仍可能被这次更新波及。

\subsection{分块并行}

Delta Rule 使得线性计算可以改写关联，但是计算顺序也因此变得更难拆开。第 $i$ 个 token 必须先看到第 $i-1$ 步更新后的状态，才能知道自己应该写入多少差值。

\begin{lstlisting}[language=Python,caption={顺序执行的 Delta 更新}]
S = torch.zeros(B, H, D, D) if cache is None else cache
outs = []
for i in range(T):
    k_i = k[:, :, i:i+1]
    v_i = v[:, :, i:i+1]
    b_i = beta[:, :, i:i+1]
    v_old = k_i @ S
    u_i = b_i * (v_i - v_old)
    S = S + k_i.transpose(-1, -2) @ u_i
    outs.append(q[:, :, i:i+1] @ S)
out = torch.cat(outs, dim=2)
\end{lstlisting}

在 decode 阶段时，Delta Rule 带来的顺序计算问题不成问题，因为 token 本来就是逐个生成的。真正的困难出现在 prefill 和训练阶段，由于会一次性出现整段输入，这个时候如果状态仍要按 token 逐步更新，就无法充分利用 GPU 的并行计算。

解决办法是把序列切成若干 chunk。chunk 之间仍按顺序传递最终状态，chunk 内部则把连续的 Delta 更新改写成矩阵运算。这样，每个位置读取的信息可以分成两部分：进入当前 chunk 以前已经积累的状态，以及当前 chunk 中更早位置刚刚写入的内容。

不过，只把序列切块还不够。chunk 内第二个位置的修正已经受到第一个位置影响，因此不能把所有 Delta 当作互不相关的外积直接相加。下面的 \texttt{Tmat} 会先整理这些先后依赖，再把结果吸收到 $W$ 和 $U$ 中。外层循环仍然逐个处理 chunk，块内的多个位置则可以一起进入矩阵计算。

\begin{lstlisting}[language=Python,caption={重参数化后的 chunk Delta 核心}]
Q, K, V = map(lambda x: x.reshape(-1, C, D), (Q, K, V))
beta = beta.reshape(-1, C)
K_beta = K * beta.unsqueeze(-1)
V_beta = V * beta.unsqueeze(-1)

Tmat = -(K_beta @ K.transpose(-1, -2)).tril(-1)
for i in range(1, C):
    Tmat[:, i, :i] += (
        Tmat[:, i, :, None] * Tmat[:, :, :i]
    ).sum(-2)
Tmat = Tmat + torch.eye(C, device=K.device)
W, U = Tmat @ K_beta, Tmat @ V_beta

for q_i, k_i, w_i, u0_i in zip(Q, K, W, U):
    u_i = u0_i - w_i @ S
    out_inter = q_i @ S
    out_intra = (q_i @ k_i.T).tril() @ u_i
    S = S + k_i.T @ u_i
    outs.append(out_inter + out_intra)
\end{lstlisting}

chunk 越大，块内可以同时计算的位置越多，$QK^{\mathsf T}$ 的开销也越高。若一个 chunk 覆盖整段序列，块内计算量会回到二次规模，但执行的仍是 Delta 更新，并不等同于标准 Softmax 注意力；若每个 chunk 只有一个 token，就回到了完全递归的实现。

代码也按这两部分组织。\texttt{out\_inter} 用 $Q_iS_{i-1}$ 读取当前 chunk 开始以前的历史；\texttt{out\_intra} 使用带因果掩码的 $Q_iK_i^{\mathsf T}$，汇总同一 chunk 内已经发生的更新。两者相加，才是当前位置能够看到的完整信息。

chunk 只是计算时的分组，不是新的上下文窗口。一个 chunk 结束后，最终状态会继续交给下一个 chunk，早期信息不会因为跨过边界就自动消失。

因此，分块没有取消 Delta Rule 的递归，而是把递归留在 chunk 之间。广义 Householder 转移矩阵负责把 chunk 内连续的“先读再改”重新参数化，让这些修正能够批量计算。模型仍然沿序列传递状态，只是不再需要为每个 token 单独启动一次计算。

\section{门控与 KDA}

\subsection{Gated DeltaNet}

Delta Rule 只有在新的 Key 到来时，才会修正与它相关的方向。可一旦话题切换，有些旧关联不会再等到明确的新值，却仍占着固定状态的容量。此时只会“改写”还不够，状态还需要主动遗忘。

Gated DeltaNet 就是来实现“遗忘”功能的，它用保留系数 $\alpha_t$ 控制每一步还留下多少旧状态。\cite{gated-delta}

\[
S_t=
\alpha_t S_{t-1}
+k_t^{\mathsf T}
\left[\beta_t\left(v_t-k_tS_{t-1}\right)\right],
\qquad 0\leq\alpha_t\leq1.
\]

\begin{lstlisting}[language=Python,caption={门控与 Delta Rule 的组合}]
S_old = cache
v_old = k @ S_old
u = beta * (v - v_old)
S = alpha * S_old + k.transpose(-1, -2) @ u
\end{lstlisting}

这个更新式同时做两件事。$\alpha_t$ 先缩放整个 $S_{t-1}$，决定旧内容保留多少；$\beta_t$ 再控制当前 Key 方向的修正幅度。前者负责遗忘，后者负责把眼前这条关联改到更接近目标 Value 的位置。

$\alpha_t=1$ 时，这一步完整保留旧状态；$\alpha_t$ 越接近零，遗忘得越多。一项信息若在第 $r$ 步写入，要留到第 $t$ 步，就必须连续通过中间的每一道门，因此累计保留比例近似为：

\[
\prod_{i=r+1}^{t}\alpha_i.
\]

例如，连续一百步都取 $\alpha=0.99$，最初的信息最后只剩约 $0.366$；若改为 $0.999$，则还能保留约 $0.905$。两个门值看起来都很接近 1，但是在经历数轮的反复相乘之后，却是天壤之别。

\subsection{Kimi Delta Attention}

Gated DeltaNet 已经能一边修正关联、一边衰减旧状态，但它的 $\alpha_t$ 仍是标量。对同一个 token 和 head 来说，所有状态通道只能一起保留，或一起遗忘。Kimi Delta Attention（KDA）把这个标量换成向量，让每个通道拥有自己的保留系数。\cite{kimi-linear}

\[
\boldsymbol{\alpha}_t
=\sigma(W_\alpha x_t),
\qquad
S_t=
\operatorname{diag}(\boldsymbol{\alpha}_t)S_{t-1}
+\Delta S_t.
\]

$\operatorname{diag}(\boldsymbol{\alpha}_t)$ 表示 $S_{t-1}$ 的不同行可以分别乘上不同系数。同一个 head 因而能够让一部分通道长期保留信息，同时让另一部分通道更快腾出空间。右侧的 $\Delta S_t$ 仍负责修正当前关联；KDA 改变的是遗忘旧状态时的控制粒度。

S = alpha[..., :, None] * S + delta     # channel gate
\end{lstlisting}

状态矩阵并没有因此变大，模型只是获得了更细的遗忘控制。训练可以让某些通道保持较大的门值，使信息延续更多 token；也可以让另一些通道迅速衰减，少受早期内容干扰。哪些通道承担长期或短期记忆，并不是事先指定的。

KDA 能累积信息、修正关联，也能逐通道清理旧内容，却没有改变固定状态本身的容量。早期 token 一旦被合并，原来的位置细节不会因为门控更精细而重新出现。若模型仍需要按位置回看完整上下文，就要保留另一条检索路径。

\section{Kimi Linear 与 Kimi K3}

\subsection{KDA 与 Kimi Linear}

Kimi Linear 没有要求固定状态独自承担全部记忆，而是把 KDA 与 Multi-head Latent Attention（MLA）交错排列。连续三层使用 KDA，通过固定大小的状态处理大部分读写；随后插入一层 MLA，对 token 序列执行 Softmax 注意力。KDA 控制主要的缓存开销，MLA 则定期补回按位置检索完整上下文的能力。

在 Kimi Linear 论文的受控实验中，这种混合结构在相同训练配置下取得了更好的模型质量。面对 1M token 的上下文时，它还将 KV Cache 用量最多减少 75\%，解码吞吐量最高提升 6 倍。这些结果说明，KDA 与 MLA 的混合结构能够降低长上下文推理的成本。

\subsection{Kimi K3}

Kimi K3 把这套混合方式扩展成 93 层主干。前 92 层组成 23 个四层周期，每个周期依次放置三层 KDA 和一层 Gated MLA；最后的第 93 层再使用一层 Gated MLA。合计下来，模型包含 69 个 KDA 层和 24 个 Gated MLA 层。\cite{kimi-k3}

四层周期把两种记忆路径固定成一种节奏：前三层连续更新压缩状态，第四层重新查看按位置保存的 token。Gated MLA 还会给检索结果加一道输出门，决定其中有多少进入残差流。模型因此不必在“固定状态”与“完整上下文”之间二选一，而是让它们承担不同频率的读取任务。

注意力之后还要经过前馈网络。Kimi K3 只有第 1 层使用稠密前馈网络，其余层都使用 LatentMoE。它包含 2 个始终参与计算的共享专家，以及 896 个由路由器选择的专家；每个 token 只会调用其中 16 个路由专家。模型共有 2.8 万亿参数，但一次只为每个 token 激活约 1040 亿参数。\cite{kimi-k3}

这两个数字描述的不是同一件事。2.8 万亿是全部专家权重，部署时仍需保存；约 1040 亿是一个 token 经过路由后实际使用的参数。MoE 减少的是单次前向传播需要参与计算的权重，并没有把模型的存储规模缩成 1040 亿参数。

Gated MLA 的 Query 投影还经过 LoRA 压缩，并在输出进入残差流前增加门控。前者缩小 Query 分支的参数与计算，后者控制本次检索结果对后续表示产生多大影响。

进入前馈网络后，token 表示会被送入选中的专家。Kimi K3 的专家使用 SiTU 激活函数：输入沿最后一维分成 gate 和 up 两部分，两条分支都用可学习参数控制双曲正切的饱和范围。

\begin{lstlisting}[language=Python,caption={SiTU 激活函数}]
d = x.shape[-1] // 2
gate = x[..., :d].to(torch.float32)
up = x[..., d:].to(torch.float32)

situ_a = (
    self.beta
    * torch.tanh(gate / self.beta)
    * torch.sigmoid(gate)
)
if self.linear_beta is not None:
    up = self.linear_beta * torch.tanh(up / self.linear_beta)
return (situ_a * up).to(x.dtype)
\end{lstlisting}

在 $x$ 接近零时，$\beta\tanh(x/\beta)$ 近似于 $x$；随着 $|x|$ 增大，输出逐渐限制在 $\pm\beta$ 附近。gate 分支还会乘上 sigmoid，up 分支则可以用另一组参数限制幅度。路由器决定一个 token 进入哪些专家，SiTU 决定专家内部怎样变换输入，二者不要混为一谈。

\subsection{AttnRes}

KDA 与 MLA 都沿 token 序列读取信息，但 Kimi K3 还有 93 层网络深度。同一个 token 穿过这些层时，表示会被反复加工，浅层结果也会逐渐混入后续残差流。深层如果想重新取用某个较早的表示，就需要另一条读取路径。AttnRes 处理的正是这个问题：MLA 检索早期 token，AttnRes 检索早期层，二者的对象并不相同。

普通残差连接会把此前各层的输出一路相加。简化以后，第 $l$ 层接收到的表示可以写成

\[
h_l=h_1+\sum_{i=1}^{l-1}f_i(h_i).
\]

其中，$f_i(h_i)$ 是第 $i$ 个子层的输出。普通残差连接默认每一项都以系数 1 加入总和，第 $l$ 层不能直接选择某个早期子层多保留一些、另一个少保留一些。层数增加以后，送到深层的表示也会混入越来越多历史输出。

Attention Residual（AttnRes）把这次固定求和改成了带权混合：

\nopagebreak[4]

\[
h_l=
\alpha_0h_1+
\sum_{i=1}^{l-1}\alpha_i f_i(h_i),
\qquad
\sum_i\alpha_i=1.
\]

计算权重时，当前子层使用一个学习得到的 pseudo-query。它是一组专门用于选择深度表示的参数，并不来自序列中的某个 token。较早的残差表示同时充当 Key 和 Value。pseudo-query 先与各个 Key 计算分数，Softmax 再沿网络深度归一化，最后按这些权重混合对应的 Value。深层由此可以偏向当前更有用的早期表示，而不必始终接受同一份固定总和。

\begin{lstlisting}[language=Python,caption={blockwise AttnRes 的核心操作}]
V = torch.stack(blocks + [partial_block])  # [N+1,B,T,D]
K = norm(V)
logits = torch.einsum(
    "d,nbtd->nbt", proj.weight.squeeze(), K)
h = torch.einsum(
    "nbt,nbtd->btd", logits.softmax(0), V)
return h
\end{lstlisting}

代码先把保存的 block 堆叠到最前面的 $N$ 维。第一次 \texttt{einsum} 为每个 token 计算它与各个深度 block 的分数，Softmax 沿 $N$ 维归一化；第二次 \texttt{einsum} 再按权重混合这些 block。输出形状仍是 $(B,T,D)$，所以后续层的接口没有改变，改变的只是它从不同深度取回信息的比例。

若保存并检索每一层，额外开销会随深度迅速增加。Kimi K3 因而采用 blockwise AttnRes：每 12 层汇总并保存一次块级表示，共形成 8 个 block，后续只在这些 block 之间计算权重。这样做降低了检索粒度，却避免了逐层保存与读取的成本。

把 GPT-2 和 Kimi K3 放在一起看，它们的基本任务并没有改变：都是 decoder-only 模型，都根据已经出现的 token 预测下一个 token；注意力、前馈网络和残差连接也仍然构成每一层的主体。不同之处在于，GPT-2 的结构比较直接：标准注意力按位置保存并检索前文，稠密前馈网络让每个 token 经过同一组参数，残差连接则把各层结果一路累加。
Kimi K3 基于这套骨架，做了不少优化：沿序列方向，多数层使用 KDA，把前文压进固定大小的状态，并通过 Delta Rule 和门控完成改写与遗忘；每隔几层再用 MLA 回到按位置保存的上下文，补回精确检索能力。沿计算方向，LatentMoE 为模型准备了大量专家，却只让每个 token 调用其中一小部分。沿网络深度，AttnRes 不再平等累加所有早期表示，而是从保存下来的 block 中选择当前更有用的部分。
因此，从 GPT-2 到 Kimi K3，真正变化的不是模型突然拥有了一个更大的“记忆盒子”。它学会了用不同方式处理不同信息：有些内容压进固定状态，随读取不断改写；有些内容保留原来的位置，需要时再精确查找。
就这样，AI酱看起来也越来越聪明，角色扮演说出来的话也渐渐的真的像初星学院的小伙伴...一样呢。

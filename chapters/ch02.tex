\section{GPT-2：作为比较的起点}

GPT-2 不是现代语言模型的起点，也不能代表 2019 年的一切。之所以从它开始，是因为它已经具有今天仍然熟悉的 decoder-only Transformer 外形，同时又足够简洁，适合拿来观察。\cite{waterloo-worklog,gpt2}

文字先被切成 token。每个 token 得到一个向量，再加上位置向量。之后，表示依次穿过 Transformer block；最后的 LayerNorm 和语言模型头把隐藏状态投影到词表，得到每个候选 token 的 logits。

\begin{lstlisting}[language=Python,caption={GPT-2 主干前向传播}]
tok_emb = self.transformer.wte(idx)       # (B, T, C)
pos_emb = self.transformer.wpe(pos)       # (T, C)
x = self.transformer.drop(tok_emb + pos_emb)
for block in self.transformer.h:
    x = block(x)
x = self.transformer.ln_f(x)
logits = self.lm_head(x)
return logits
\end{lstlisting}

一个 block 里有两次熟悉的动作：先做因果自注意力，再做 MLP。两者都采用 pre-norm，并通过残差连接把新结果加回原表示。

\begin{lstlisting}[language=Python,caption={带注意力与 MLP 的 Transformer block}]
class Block(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.ln_1 = LayerNorm(config.n_embd)
        self.attn = CausalSelfAttention(config)
        self.ln_2 = LayerNorm(config.n_embd)
        self.mlp = MLP(config)

    def forward(self, x):
        x = x + self.attn(self.ln_1(x))
        x = x + self.mlp(self.ln_2(x))
        return x
\end{lstlisting}

自注意力把输入投影成 Query、Key 和 Value。对当前位置的 Query 来说，Key 决定应该注意哪些位置，Value 提供从那些位置取回的内容。因果掩码遮住未来，Softmax 则把分数变成总和为一的权重。

\[
\operatorname{Attn}(Q,K,V)
=
\operatorname{softmax}\left(
\frac{QK^{\mathsf T}}{\sqrt{d}}
+M_{\mathrm{causal}}
\right)V
\]

生成下一个 token 时，真正用于采样的只有最后一个位置的 logits。若每生成一步都重新计算整段前文，早期 token 的 Key 和 Value 也会被重复投影。KV Cache 的做法很直接：把已经算过的 Key、Value 留下来；下一步只为新 token 计算一份，再与缓存拼接。

\begin{lstlisting}[language=Python,caption={带 KV Cache 的 Softmax 注意力核心}]
q, k, v = split_heads(self.qkv_proj(x))

if past_kv is not None:
    k_past, v_past = past_kv
    k = torch.cat((k_past, k), dim=2)
    v = torch.cat((v_past, v), dim=2)

scores = (q @ k.transpose(-1, -2)) / math.sqrt(d_head)
if past_kv is None:
    scores = scores.masked_fill(causal_mask, float("-inf"))

attn = scores.softmax(dim=-1)
out = attn @ v
return self.o_proj(merge_heads(out)), (k, v)
\end{lstlisting}

这样避免了重复计算。不过，前文每增加一个 token，缓存中也会多出一对 Key、Value。计算被省下来了，记忆占用却会随上下文一起增长。后面的几种设计，都在尝试改变这种保存历史的方法。

\section{线性注意力：把历史折叠成固定状态}

线性注意力论文中的复杂度描述，放在今天读，容易让人迟疑。现在通常用 KV Cache 讨论解码，用 FlashAttention 讨论完整注意力矩阵的读写；但论文写于 2020 年。回到当时的实现语境，问题会清楚一些。\cite{linear-transformer}

Softmax 注意力先让每个 Query 与每个 Key 相乘，再对这些成对分数施加指数与归一化。非线性夹在中间，乘法次序不能随意交换。线性注意力改为分别映射 Query 和 Key：

\[
\phi(q)=\operatorname{ELU}(q)+1,\qquad
\phi(k)=\operatorname{ELU}(k)+1.
\]

于是，历史可以先聚合成固定大小的状态

\[
S_t=\sum_{i=1}^{t}\phi(k_i)^{\mathsf T}v_i,
\qquad
z_t=\sum_{i=1}^{t}\phi(k_i),
\]

再由当前 Query 读取：

\[
o_t=
\frac{\phi(q_t)S_t}
     {\phi(q_t)z_t}.
\]

\begin{lstlisting}[language=Python,caption={把历史 K、V 折叠进固定状态}]
q, k, v = split_heads(self.qkv_proj(x))
q = F.elu(q) + 1
k = F.elu(k) + 1

S, z = cache if cache is not None else (0.0, 0.0)
S = S + k.transpose(-1, -2) @ v
z = z + k.sum(dim=-2, keepdim=True)

out = q @ S
denom = q @ z.transpose(-1, -2)
out = out / denom.clamp_min(1e-6)
return self.o_proj(merge_heads(out)), (S, z)
\end{lstlisting}

这个改写很漂亮，但交换条件也很明确。KV Cache 为每个早期 token 保留独立的 Key 和 Value；固定状态只有有限的矩阵槽位。新的关联不断相加以后，早期信息不再彼此分离，甚至会相互干扰。空间不再随序列增长，代价是不能无损保存任意长的历史。

此外，$\operatorname{ELU}+1$ 只是在 Softmax kernel 之外选择了一种可分解的非负特征映射。它仍然完成“非负权重、归一化、Value 加权平均”这三件事，却不等价于原来的 Softmax 表达。

\section{DeltaNet：修改旧关联}

如果固定状态只会执行

\[
S_t=S_{t-1}+k_t^{\mathsf T}v_t,
\]

那么同一个方向上的新旧信息只会叠在一起。序列长到超过有效容量时，状态会逐渐变成许多关联的混合物。

Delta Rule 的想法不是继续添加完整的新 Value，而是先用当前 Key 读一次，看看这个位置已经保存了什么。\cite{fast-weight}

\begin{lstlisting}[language=Python,caption={带逐 token 写入强度的 Delta 更新}]
q, k, v = split_heads(self.qkv_proj(x))
q = F.normalize(F.silu(q), dim=-1)
k = F.normalize(F.silu(k), dim=-1)
beta = torch.sigmoid(self.w_beta(x)).view(B, 1, T, 1)

S = cache if cache is not None else 0.0
v_old = k @ S
u = beta * (v - v_old)
S = S + k.transpose(-1, -2) @ u

out = q @ S
return self.o_proj(merge_heads(out)), S
\end{lstlisting}

这里的 $\beta$ 是写入强度。若 Key 已归一化，同一个 Key 从 $k^{\mathsf T}v$ 中读回的就是 $v$。所以 $v-v_{\mathrm{old}}$ 表示真正需要补上的差值：旧内容被抵消，新内容写回同一方向。

可以把它理解成一块容量有限的白板。纯加法每次都在旧字上继续写；Delta Rule 先辨认同一位置原来写了什么，再只补上需要改变的部分。它提高了可修改性，却仍然没有回答另一件事：怎样一次清理整块白板上已经不再重要的内容。

\section{分块并行：在块内展开，在块间递归}

DeltaNet 的状态依赖前一步状态。逐 token 写出来很简单：

\begin{lstlisting}[language=Python,caption={顺序执行的 Delta 更新}]
S = torch.zeros(B, H, D, D) if cache is None else cache
outs = []
for i in range(T):
    k_i = k[:, :, i:i+1]
    v_i = v[:, :, i:i+1]
    b_i = beta[:, :, i:i+1]
    v_old = k_i @ S
    u_i = b_i * (v_i - v_old)
    S = S + k_i.transpose(-1, -2) @ u_i
    outs.append(q[:, :, i:i+1] @ S)
out = torch.cat(outs, dim=2)
\end{lstlisting}

但这也意味着，预填充一段长文本时，后一个 token 要等待前一个 token 更新完状态。为了把一部分工作重新变成矩阵计算，可以把序列分成 chunk。

在一个 chunk 内，使用因果掩码同时计算当前位置之间的影响；不同 chunk 之间，只传递已经压缩好的状态。于是每个输出由两部分组成：从进入本块之前的状态读到的内容，以及本块内部此前位置贡献的内容。

\begin{lstlisting}[language=Python,caption={重参数化后的 chunk Delta 核心}]
Q, K, V = map(lambda x: x.reshape(-1, C, D), (Q, K, V))
beta = beta.reshape(-1, C)
K_beta = K * beta.unsqueeze(-1)
V_beta = V * beta.unsqueeze(-1)

Tmat = -(K_beta @ K.transpose(-1, -2)).tril(-1)
for i in range(1, C):
    Tmat[:, i, :i] += (
        Tmat[:, i, :, None] * Tmat[:, :, :i]
    ).sum(-2)
Tmat = Tmat + torch.eye(C, device=K.device)
W, U = Tmat @ K_beta, Tmat @ V_beta

for q_i, k_i, w_i, u0_i in zip(Q, K, W, U):
    u_i = u0_i - w_i @ S
    out_inter = q_i @ S
    out_intra = (q_i @ k_i.T).tril() @ u_i
    S = S + k_i.T @ u_i
    outs.append(out_inter + out_intra)
\end{lstlisting}

chunk 等于整个序列时，它接近完整注意力；chunk 只有一个 token 时，它退回完全递归的形式。中间大小是在块内并行量与块间递归之间取平衡。

Delta Rule 比纯加法更麻烦，因为每次修正都依赖“写入前读到的旧值”。论文通过重新参数化，把一个 chunk 内的连续修正整理为能够并行求出的块，再用同样的“块内结果 + 块前状态”组合输出。这里不继续展开 Householder 矩阵推导。对后文最重要的结论只有一个：递归记忆并不等于训练时必须逐 token 串行；它可以在块边界上保留递归，同时把块内部交给矩阵运算。

\section{Gated DeltaNet：让旧状态衰减}

Delta Rule 擅长替换某一条已经找到的关联。若上下文突然切换，它却没有一个简单动作，可以让许多旧关联一起淡出。

门控更新给旧状态乘上 $\alpha_t$。\cite{gated-delta}

\[
S_t=
\alpha_t S_{t-1}
+k_t^{\mathsf T}
\left[\beta_t\left(v_t-k_tS_{t-1}\right)\right],
\qquad 0\leq\alpha_t\leq1.
\]

\newpage
\begin{lstlisting}[language=Python,caption={门控与 Delta Rule 的组合}]
S_old = cache
v_old = k @ S_old
u = beta * (v - v_old)
S = alpha * S_old + k.transpose(-1, -2) @ u
\end{lstlisting}

$\alpha_t=1$ 时，旧状态完整保留；$\alpha_t$ 接近零时，过去大范围衰减。某项信息经过多步以后，会累计乘上中间所有门值。于是模型同时获得两种操作：Delta Rule 对一个 Key 方向做定点修正，门控则管理整体记忆寿命。

它们并不重复。只会衰减的系统无法精确替换一条关联；只会 Delta 更新的系统又缺少广泛遗忘。Gated DeltaNet 把这两种能力放进同一个固定状态更新中。

\section{KDA：更细粒度的记忆门}

Gated DeltaNet 的 $\alpha_t$ 是一个标量。同一时间步里，不同通道都按相同比例保留旧状态。Kimi Delta Attention（KDA）把门变成向量，让各通道拥有不同的衰减速度。\cite{kimi-linear}

\[
\boldsymbol{\alpha}_t
=\sigma(W_\alpha x_t),
\qquad
S_t=
\operatorname{diag}(\boldsymbol{\alpha}_t)S_{t-1}
+\Delta S_t.
\]

\begin{lstlisting}[language=Python,caption={三种状态更新在实现上的差别}]
# Delta Rule: no decay
S = S + delta

# Gated DeltaNet: one scalar per token/head
S = alpha[..., None, None] * S + delta

# KDA: one decay value for every state channel
S = alpha[..., :, None] * S + delta
\end{lstlisting}

这项变化看起来很小，却改变了容量的分配方式。模型可以让某些通道快速忘记局部信息，同时让另一些通道保留更久。固定状态仍然有限，但“哪些方向应该腾出空间”不再只有一个统一答案。

Kimi Linear 并没有要求所有层都只使用这种递归记忆。它把 KDA 与 Multi-head Latent Attention（MLA）交错使用：多数层依靠固定状态处理历史，周期性的 MLA 层仍能对 token 上下文执行 Softmax 检索。前者控制持续增长的缓存，后者保留精确回看具体位置的能力。

\section{Kimi K3：把不同记忆机制组合起来}

Kimi K3 值得注意的地方，不是某个单独的全新模块，而是这些模块怎样被安排在一起。\cite{kimi-k3}

它的注意力主干反复采用“三层 KDA、一层 Gated MLA”的节奏。官方架构汇总中共有 69 个 KDA 层与 24 个 Gated MLA 层。第一层使用稠密前馈网络，之后的前馈部分主要使用 LatentMoE：每个 token 不必经过全部专家，而是由路由器选择少数专家，并保留共享专家。

这套组合里，每种容量有不同职责：

\begin{itemize}[leftmargin=1.5em]
  \item KDA 用固定大小的递归状态保存和更新关联；
  \item Gated MLA 周期性地回到 token 级上下文，执行选择性检索；
  \item LatentMoE 把前馈容量分散到专家，只激活与当前 token 相关的一小部分；
  \item 门控决定从注意力输出中放多少信息进入残差流；
  \item AttnRes 则沿模型深度回看较早的表示。
\end{itemize}

所以，从 GPT-2 走到这里，改变的不只是“层更多”。历史信息不再只有一条保存路线：有些被压进递归状态，有些仍留在 token 上下文中等待完整注意力取回，计算容量通过专家路由分配，深层网络还会重新选择较早的中间表示。

Kimi K3 的专家网络还采用 SiTU 激活。输入先沿最后一维分成 gate 与 up 两半；可学习参数控制双曲正切的截断范围，再与 sigmoid 门相乘。

\begin{lstlisting}[language=Python,caption={SiTU 激活函数}]
d = x.shape[-1] // 2
gate = x[..., :d].to(torch.float32)
up = x[..., d:].to(torch.float32)

situ_a = (
    self.beta
    * torch.tanh(gate / self.beta)
    * torch.sigmoid(gate)
)
if self.linear_beta is not None:
    up = self.linear_beta * torch.tanh(up / self.linear_beta)
return (situ_a * up).to(x.dtype)
\end{lstlisting}

\section{AttnRes：沿深度选择较早的表示}

普通残差网络把此前各层的输出不断相加。用简化写法表示，第 $l$ 层看到的是

\[
h_l=h_1+\sum_{i=1}^{l-1}f_i(h_i).
\]

所有历史层默认以同样的加法进入当前状态。网络当然可以在后续层里学习抵消或放大，但它不能直接说：“这次更需要第 4 层的表示，少看一点第 20 层。”

Attention Residual（AttnRes）把固定求和改为带权混合：

\[
h_l=
\alpha_0h_1+
\sum_{i=1}^{l-1}\alpha_i f_i(h_i),
\qquad
\sum_i\alpha_i=1.
\]

这些权重来自当前层的 Query 与较早残差表示的 Key 之间的匹配。早期表示同时作为 Value，被按权重重新组合。

\begin{lstlisting}[language=Python,caption={blockwise AttnRes 的核心操作}]
V = torch.stack(blocks + [partial_block])  # [N+1,B,T,D]
K = norm(V)
logits = torch.einsum(
    "d,nbtd->nbt", proj.weight.squeeze(), K
)
h = torch.einsum(
    "nbt,nbtd->btd", logits.softmax(0), V
)
return h
\end{lstlisting}

若每一层都保存并检索全部早期状态，成本仍会增长。Kimi K3 使用 blockwise 形式：先在一组层内累积普通残差，只在固定边界保存一个块级表示；后面的边界再从这些块中选择。它与 MLA 的检索方向不同。MLA 沿序列长度回看 token，AttnRes 沿网络深度回看中间表示。

\section{回到活动室}

讲解到这里，结构图也缩回了一页。

从 GPT-2 到 Kimi K3，最容易看到的是规模增长；但只看规模，会漏掉模型内部保存信息的方法已经发生的变化。

GPT-2 的 Softmax 注意力保留 token 级的 Key 与 Value。线性注意力把历史压进固定状态。Delta Rule 让状态可以定点改写，门控让旧内容能够衰减，KDA 又把衰减细化到不同通道。Kimi K3 没有把一种机制用到底，而是让递归状态、周期性完整检索、专家路由和深度方向的残差检索各自承担一部分工作。

“所以，AI 酱变聪明，就是因为这些吗？”佑芽问。

“只是一部分。”

我关掉代码窗口。

“模型结构决定它怎样计算、保存和取回信息。训练数据、训练方法、后训练，还有使用时提供的上下文，也都在改变回答。今天只观察了最容易从公开实现里看清的一条线。”

千奈又看了一遍屏幕里的周末计划。

“那……跑去游乐园这件事呢？”

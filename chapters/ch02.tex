\section{GPT-2}

对话框中的 AI 佑芽，看起来像是一口气相应了一整句话，但是模型内部却没有“一口气”这回事。它每次只往前走一小步：读取已经出现的文字，给接下来可能出现的文字片段打分，选出权重最高的那个接到末尾，然后再重复执行下一步。一句完整的回答，就是这样一点点续出来的。

 这种只根据前文一步步续写的方式，叫作自回归生成。GPT-2 是 OpenAI 在 2019 年发布的语言模型，也是 GPT 系列的第二代。它采用纯解码器 Transformer：输入只有已经出现的文字，模型不能偷看后文，只能沿着前文继续预测。GPT-2 虽然是7年前的老模型，但它的结构已经具备本章后面还会反复看到的基本轮廓，公开实现也相对简洁，所以适合作为这次的起点。\cite{waterloo-worklog,gpt2}

再处理用户发起的请求时，模型会先将输入内容切成 token，它代表着模型实际读写的片段。一个 token 可能是一个字、一个词的一部分，也可能是标点；具体怎样切，由分词器决定。我们在聊天时的提示词、聊天记录和已经生成的回答，都会先被处理成这样一串 token，在推测下一个字符应该是什么的过程中，gpt-2会给清单中的候选 token 各打一个分。这些尚未归一化的分数叫作 logits，生成程序会按照解码规则选出一个最优选的 token，把它接回前文，模型再根据变长后的前文给同一张词表重新打分。

从 token 到 logits，中间要经过下面这条主干。词嵌入先回答“这是什么 token”，位置嵌入补上“它出现在第几个位置”；两者相加后进入一层层 Transformer block。最后，词表投影再把内部向量翻译成每个候选 token 的分数。

\begin{lstlisting}[language=Python,caption={GPT-2 主干前向传播}]
tok_emb = self.transformer.wte(idx)       # (B, T, C)
pos_emb = self.transformer.wpe(pos)       # (T, C)
x = self.transformer.drop(tok_emb + pos_emb)
for block in self.transformer.h:
    x = block(x)
x = self.transformer.ln_f(x)
logits = self.lm_head(x)
return logits
\end{lstlisting}

我们暂时不关心批量计算，先忽略注释里的 $B$。$T$ 表示这次读入多少个 token，$C$ 表示每个 token 用多长的向量来表示。词嵌入的形状是 $(B,T,C)$；位置嵌入没有批量维，会复用到同一批的每条序列上。后面的 block 始终接收并返回类型不变的 \texttt{x}。

被反复加工内容的是 \texttt{x = block(x)}。一个 block 里，因果自注意力毁让较后的 token 利用已经出现的前文，MLP 再逐个位置处理汇集后的特征。计算结果通过残差连接加回原表示，所以每一层做的更像是在已有理解上补一笔，而不是把整句话推倒重算。

\begin{lstlisting}[language=Python,caption={带注意力与 MLP 的 Transformer block}]
class Block(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.ln_1 = LayerNorm(config.n_embd)
        self.attn = CausalSelfAttention(config)
        self.ln_2 = LayerNorm(config.n_embd)
        self.mlp = MLP(config)

    def forward(self, x):
        x = x + self.attn(self.ln_1(x))
        x = x + self.mlp(self.ln_2(x))
        return x
\end{lstlisting}

一次注意力计算从 Query、Key 和 Value 三组投影开始。对第 $i$ 个 token 来说，它的 Query 要和当前位置以及前面各个位置的 Key 比较，再从对应的 Value 中取回信息。这个过程可以写成：

\[
\operatorname{Attn}(Q,K,V)
=
\operatorname{softmax}\left(
\frac{QK^{\mathsf T}}{\sqrt{d}}
+M_{\mathrm{causal}}
\right)V
\]

式中的 $d$ 是一个 head 的维度。除以 $\sqrt d$ 是为了缩放点积分数；$M_{\mathrm{causal}}$ 则把未来位置挡住，使第 $i$ 个 token 只能看到它自己和此前的内容。Softmax 随后把剩余分数变成权重，加权汇总对应的 Value。

Key 决定“从哪里取”，Value 决定“取回什么”，两者分工不同。多个 head 使用各自的投影并行计算，所得结果拼接以后，再通过输出投影回到隐藏维度。这个新表示会继续经过后面的层，并最终影响词表中的候选分数。

上面的公式只描述了一次注意力计算。一条完整回复还要反复运行模型：每得到一个 token，就把它接到已有序列末尾，再计算下一个。“下车以后再跑”看起来是一句话，模型实际完成的是若干次这样的续写。

第一次运行时，提示词、人物说明和聊天记录都已经存在。模型会一次处理这段输入，并算出各层、各个位置的 Key 和 Value；这一阶段叫作 \textit{prefill}。

此后进入 \textit{decode}。每一轮只多出一个 token：它经过模型各层，与此前内容计算注意力，最后一个位置的 logits 再交给解码程序选出后续 token。新结果接回序列，下一轮继续。

如果每轮都从头计算，提示词和已经生成的回复会被反复投影成同样的 Key 和 Value。KV Cache 把各层已经算出的 Key 和 Value 留下来。decode 时只需计算新 token 的投影，让它的 Query 读取缓存中的历史，再把新得到的 Key、Value 追加到末尾。

\begin{lstlisting}[language=Python,caption={带 KV Cache 的 Softmax 注意力核心}]
q, k, v = split_heads(self.qkv_proj(x))

if past_kv is not None:
    k_past, v_past = past_kv
    k = torch.cat((k_past, k), dim=2)
    v = torch.cat((v_past, v), dim=2)

scores = (q @ k.transpose(-1, -2)) / math.sqrt(d_head)
if past_kv is None:
    scores = scores.masked_fill(causal_mask, float("-inf"))

attn = scores.softmax(dim=-1)
out = attn @ v
return self.o_proj(merge_heads(out)), (k, v)
\end{lstlisting}

KV Cache 省下的是重算，并没有省掉历史本身。序列每增加一个 token，缓存仍要增加一组 Key 和 Value；上下文越长，decode 时需要保存和读取的内容也越多。接下来要问的是：能不能不再逐个保存这些 K、V，却仍让后面的 token 用到前文？

\section{线性注意力与固定状态}

线性注意力给出的办法，是不再为每个早期 token 保留独立的 Key 和 Value，而是把它们逐步合并到一个固定大小的状态中。缓存不再随序列长度增长，代价是注意力的计算方式也必须改变。\cite{linear-transformer}

标准注意力先计算 $QK^{\mathsf T}$，再做 Softmax。由于 Softmax 位于两次矩阵乘法之间，不能简单地把计算改写成 $Q(K^{\mathsf T}V)$。线性注意力改为分别映射 Query 和 Key，例如：

\[
\phi(q)=\operatorname{ELU}(q)+1,\qquad
\phi(k)=\operatorname{ELU}(k)+1.
\]

映射后的结果为正，后续归一化也可以拆开计算。此前的 Key 和 Value 便能先合并为两个状态：

\[
S_t=\sum_{i=1}^{t}\phi(k_i)^{\mathsf T}v_i,
\qquad
z_t=\sum_{i=1}^{t}\phi(k_i),
\]

第 $t$ 个 Query 再从中计算输出：

\[
o_t=
\frac{\phi(q_t)S_t}
     {\phi(q_t)z_t}.
\]

这里的 $S_t$ 累积 Key 与 Value 的外积，$z_t$ 累积映射后的 Key，用于分母中的归一化。只要 head 维度不变，两者的形状就不会随序列长度改变。decode 不再携带全部 K、V，只需携带当前的 $S_t$ 和 $z_t$。

$S_t$ 记录的是“各个 Key 方向累计写入了哪些 Value”，$z_t$ 则记录这些方向一共积累了多少权重。Query 乘上 $S_t$ 得到加权后的 Value 总量，再除以 Query 乘上 $z_t$ 得到的权重总量。少了 $z_t$，序列越长，状态中累积的数值通常也会越大，输出就不再对应归一化的加权平均。

$\operatorname{ELU}+1$ 只是一种可拆分计算的非负特征映射，并不等同于 Softmax。两种方法都会归一化分数并对 Value 求加权和，但它们产生权重的方式不同，不能把线性注意力理解成对标准注意力的等价改写。

\begin{lstlisting}[language=Python,caption={把历史 K、V 折叠进固定状态}]
q, k, v = split_heads(self.qkv_proj(x))
q = F.elu(q) + 1
k = F.elu(k) + 1

S, z = cache if cache is not None else (0.0, 0.0)
S = S + k.transpose(-1, -2) @ v
z = z + k.sum(dim=-2, keepdim=True)

out = q @ S
denom = q @ z.transpose(-1, -2)
out = out / denom.clamp_min(1e-6)
return self.o_proj(merge_heads(out)), (S, z)
\end{lstlisting}

固定状态节省空间的方式，是把不同位置的信息写入同一个矩阵。它无法像 KV Cache 那样，始终为每个 token 保留一份相互分离的 Key 和 Value。写入次数超过状态可以清楚区分的范围后，不同关联就会互相干扰。

这种干扰可以从更新式直接看出来。若两个 Key 的方向接近，它们的外积会写入 $S_t$ 的相近部分；纯加法只会把新的 Value 继续叠上去，不能先移除旧关联。之后沿这个方向查询时，输出便可能同时包含新旧两次写入的成分。

因此，固定状态带来了新的问题：在不恢复逐 token 缓存的前提下，怎样修改已经写入的关联？

\subsection{Delta Rule}

固定状态的纯加法可以写成：

\[
S_t=S_{t-1}+k_t^{\mathsf T}v_t,
\]

Delta Rule 修改了写入动作。它先用当前 Key 从状态中读出旧值，再计算目标 Value 与旧值的差，只把这部分差写回状态。\cite{fast-weight}

\begin{lstlisting}[language=Python,caption={带逐 token 写入强度的 Delta 更新}]
q, k, v = split_heads(self.qkv_proj(x))
q = F.normalize(F.silu(q), dim=-1)
k = F.normalize(F.silu(k), dim=-1)
beta = torch.sigmoid(self.w_beta(x)).view(B, 1, T, 1)

S = cache if cache is not None else 0.0
v_old = k @ S
u = beta * (v - v_old)
S = S + k.transpose(-1, -2) @ u

out = q @ S
return self.o_proj(merge_heads(out)), S
\end{lstlisting}

这里的 $\beta$ 控制本次更新的强度。Key 经过归一化后，如果状态中只有关联 $k^{\mathsf T}v$，再用同一个 $k$ 读取，就会得到 $v$。因此，$v-v_{\mathrm{old}}$ 表示当前读出与目标值之间的误差。

从同一个 Key 方向把更新式再读一次，效果会更清楚。记 $v_{\mathrm{old}}=k_tS_{t-1}$，并令 $\lVert k_t\rVert=1$，则

\[
k_tS_t=(1-\beta_t)v_{\mathrm{old}}+\beta_t v_t.
\]

$\beta_t=0$ 时状态不变；$\beta_t=1$ 时，当前 Key 方向的读出更新为目标 Value；中间值则在两者之间插值。这个结论依赖单位 Key 的简化条件，相近方向上的其他关联仍可能受到更新影响。

\subsection{分块并行}

Delta Rule 可以修改已有的关联，但第 $i$ 个 token 的更新仍然依赖第 $i-1$ 步留下的状态。按 token 顺序实现时，代码很直接：

\begin{lstlisting}[language=Python,caption={顺序执行的 Delta 更新}]
S = torch.zeros(B, H, D, D) if cache is None else cache
outs = []
for i in range(T):
    k_i = k[:, :, i:i+1]
    v_i = v[:, :, i:i+1]
    b_i = beta[:, :, i:i+1]
    v_old = k_i @ S
    u_i = b_i * (v_i - v_old)
    S = S + k_i.transpose(-1, -2) @ u_i
    outs.append(q[:, :, i:i+1] @ S)
out = torch.cat(outs, dim=2)
\end{lstlisting}

这种顺序依赖在 decode 阶段不是主要问题，因为下一个 token 本来就要等上一个 token 生成。训练和 prefill 则不同：整段输入已经给出，如果每个位置仍要等待前一个位置更新完状态，就无法充分并行计算。

一种实现办法是把序列切成若干 chunk。块与块之间继续顺序传递状态，块内则把递归更新重新参数化成矩阵运算。于是，一个块的输出由两部分组成：从前一个块继承的状态，以及当前块内较早位置产生的更新。

难点在于，块内第二个位置的修正已经受第一个位置影响，不能把所有 Delta 当成彼此独立的外积一次相加。下面的 \texttt{Tmat} 正是用来整理这种块内依赖：它把较早 Key 对较晚更新的影响吸收到 $W$ 和 $U$ 中。外层仍按块推进，块内才有机会改写成适合矩阵乘法的计算。

\begin{lstlisting}[language=Python,caption={重参数化后的 chunk Delta 核心}]
Q, K, V = map(lambda x: x.reshape(-1, C, D), (Q, K, V))
beta = beta.reshape(-1, C)
K_beta = K * beta.unsqueeze(-1)
V_beta = V * beta.unsqueeze(-1)

Tmat = -(K_beta @ K.transpose(-1, -2)).tril(-1)
for i in range(1, C):
    Tmat[:, i, :i] += (
        Tmat[:, i, :, None] * Tmat[:, :, :i]
    ).sum(-2)
Tmat = Tmat + torch.eye(C, device=K.device)
W, U = Tmat @ K_beta, Tmat @ V_beta

for q_i, k_i, w_i, u0_i in zip(Q, K, W, U):
    u_i = u0_i - w_i @ S
    out_inter = q_i @ S
    out_intra = (q_i @ k_i.T).tril() @ u_i
    S = S + k_i.T @ u_i
    outs.append(out_inter + out_intra)
\end{lstlisting}

若一个 chunk 覆盖整段序列，块内交互会回到二次计算量，但其中执行的仍是 Delta 更新，并不等同于标准 Softmax 注意力。若 chunk 只含一个 token，算法就退化为完全递归的实现。chunk 大小由此决定块内并行与块间顺序更新的比例。

图中的两项对应代码里的两个输出：$\texttt{out\_inter}=Q_iS_{i-1}$ 读取进入当前块以前的状态，$\texttt{out\_intra}$ 用带因果掩码的 $Q_iK_i^{\mathsf T}$ 汇总块内较早位置的更新。两部分相加得到当前块的输出。

chunk 规定的是计算粒度，不是上下文窗口。一个块结束后，最终状态仍会交给下一个块，因此较早信息不会仅因跨过块边界而被丢弃。

Delta 更新之所以难以直接并行，是因为每次修正都要先知道更新前的读出。论文使用广义 Householder 转移矩阵重新参数化块内的连续更新，把它们整理成可以批量计算的矩阵。状态仍在块间递归，块内计算则可以使用矩阵运算并行完成。

\section{门控与 KDA}

\subsection{Gated DeltaNet}

Delta Rule 只会在新的 Key 到来时修正相关方向。如果上下文已经切换，一些旧关联可能再也等不到对应的新值，却仍保留在固定状态中。要释放这部分容量，还需要让旧状态随时间衰减。

Gated DeltaNet 为旧状态增加了保留系数 $\alpha_t$。\cite{gated-delta}

\[
S_t=
\alpha_t S_{t-1}
+k_t^{\mathsf T}
\left[\beta_t\left(v_t-k_tS_{t-1}\right)\right],
\qquad 0\leq\alpha_t\leq1.
\]

\begin{lstlisting}[language=Python,caption={门控与 Delta Rule 的组合}]
S_old = cache
v_old = k @ S_old
u = beta * (v - v_old)
S = alpha * S_old + k.transpose(-1, -2) @ u
\end{lstlisting}

式中，$\alpha_t$ 先缩放整个旧状态，$\beta_t$ 再控制当前 Key 方向上的 Delta 更新强度。前者决定旧状态整体保留多少，后者决定本次误差修正多少。两项计算共同得到新的 $S_t$。

\[
\prod_{i=r+1}^{t}\alpha_i.
\]

连续一百步都取 $\alpha=0.99$，累计保留比例约为 $0.366$；若取 $0.999$，则约为 $0.905$。即使单步门值都接近 1，长序列上的累计差异也会很明显。

\subsection{Kimi Delta Attention}

Gated DeltaNet 同时具备误差修正和状态衰减，但每个 token、每个 head 的 $\alpha_t$ 仍是一个标量。在同一个时间步内，该 head 的所有状态通道都按相同比例缩放。Kimi Delta Attention（KDA）把标量门改成向量门，让不同通道使用不同的保留系数。\cite{kimi-linear}

\[
\boldsymbol{\alpha}_t
=\sigma(W_\alpha x_t),
\qquad
S_t=
\operatorname{diag}(\boldsymbol{\alpha}_t)S_{t-1}
+\Delta S_t.
\]

对角矩阵的写法表示，$S_{t-1}$ 的不同行可以乘上不同的系数。于是，同一个 head 在同一步里也能让一部分通道缓慢遗忘，让另一部分通道迅速让位给新内容。Delta 项仍负责修正当前 Key 指向的关联；KDA 改变的是旧状态被保留的粒度。

向量门没有增加状态矩阵的大小，改变的是各通道的衰减粒度。训练后，一些通道可以保留较大的门值，让信息经过更多 token；另一些通道可以更快衰减，减少较早内容对当前状态的影响。至于各通道最终承担什么功能，并没有预先规定。

\section{Kimi Linear 与 Kimi K3}

\subsection{KDA 与 Kimi Linear}

Kimi Linear 将 KDA 与 Multi-head Latent Attention（MLA）交错排列。多数层使用 KDA，在固定状态上完成读写；每隔三层插入一层 MLA，对 token 序列执行一次 Softmax 注意力。前者控制大部分层的缓存大小，后者保留按位置检索上下文的能力。

Kimi Linear 论文报告，在其受控实验中，这种混合结构的质量超过对应的全注意力基线，解码吞吐量最高提升 6 倍。该结果依赖论文给定的模型、任务与硬件条件，不能直接外推到所有部署。\cite{kimi-linear}

\subsection{Kimi K3}

Kimi K3 沿用了 Kimi Linear 的混合方式。前 92 层由 23 个四层周期组成，每个周期依次包含三层 KDA 和一层 Gated MLA；第 93 层再使用一层 Gated MLA。整条主干因此共有 69 个 KDA 层和 24 个 Gated MLA 层。\cite{kimi-k3}

在每个周期中，前三层通过 KDA 读取并更新固定状态；第四层通过 MLA 访问按位置保存的 token 上下文。MLA 的输出还要经过门控，模型可以调节这次检索结果写入残差流的比例。两种注意力分别保留固定状态的空间优势和 Softmax 注意力的位置检索能力。

每层注意力之后还有前馈网络。第 1 层使用稠密前馈网络，其余层使用 LatentMoE。LatentMoE 包含 896 个路由专家和 2 个共享专家：共享专家始终参与，路由器再为每个 token 选择 16 个路由专家。Kimi K3 的总参数量为 2.8 万亿，但每个 token 只激活约 1040 亿参数。MoE 由此把模型的总参数容量与单个 token 实际经过的计算量分开。\cite{kimi-k3}

这里的两个参数量不能互相替代。2.8 万亿描述模型拥有的全部专家权重，部署时仍要容纳这些权重；约 1040 亿描述一个 token 经过路由以后实际调用的部分。MoE 节省的是每次前向传播都遍历全部参数的计算，并不是把整个模型缩成了 1040 亿参数。

Gated MLA 还使用 Query LoRA 压缩 Query 投影，并在输出进入残差流以前增加门控。Query LoRA 减少这一分支的参数与计算，输出门则调节注意力结果的写入强度。

注意力更新完成后，token 表示进入前馈网络。Kimi K3 的专家使用 SiTU 激活函数：输入沿最后一维分成 gate 与 up 两部分，两条分支都可以用可学习参数控制双曲正切的饱和范围。

\begin{lstlisting}[language=Python,caption={SiTU 激活函数}]
d = x.shape[-1] // 2
gate = x[..., :d].to(torch.float32)
up = x[..., d:].to(torch.float32)

situ_a = (
    self.beta
    * torch.tanh(gate / self.beta)
    * torch.sigmoid(gate)
)
if self.linear_beta is not None:
    up = self.linear_beta * torch.tanh(up / self.linear_beta)
return (situ_a * up).to(x.dtype)
\end{lstlisting}

式中的 $\beta\tanh(x/\beta)$ 在零附近近似 $x$，输入的绝对值增大后则趋近 $\pm\beta$。Gate 分支还要乘以 sigmoid，up 分支可以使用另一组参数完成同样的限制。路由器负责选择专家，SiTU 负责专家内部的非线性变换，两者处在不同层次。

\subsection{AttnRes}

KDA 与 MLA 处理的是 token 序列上的信息传递。Kimi K3 有 93 层，表示在网络深度上的传递也需要处理：后面的层怎样使用较早层产生的表示？

这是另一条轴。KDA 和 MLA 讨论同一层里，当前 token 怎样取得前面 token 的信息；接下来的 AttnRes 讨论同一个 token 穿过许多层以后，深层计算怎样重新取用浅层表示。两种机制都使用“注意力”，检索的对象却不同。

普通残差网络不断累加此前各层的输出。用简化写法表示，第 $l$ 层看到的是

\[
h_l=h_1+\sum_{i=1}^{l-1}f_i(h_i).
\]

其中，$f_i(h_i)$ 表示第 $i$ 个子层的输出。普通残差连接以相同系数累加这些结果，第 $l$ 层无法直接调节某个早期子层所占的比例。网络越深，需要合并的历史层输出也越多。

Attention Residual（AttnRes）把固定求和改为带权混合：

\nopagebreak[4]

\[
h_l=
\alpha_0h_1+
\sum_{i=1}^{l-1}\alpha_i f_i(h_i),
\qquad
\sum_i\alpha_i=1.
\]

AttnRes 为每个子层学习一个 pseudo-query，较早的残差表示同时作为 Key 和 Value。pseudo-query 与这些 Key 计算分数，Softmax 沿网络深度归一化，随后按权重合并对应的 Value。这样，第 $l$ 层接收的不再是固定的历史层总和，而是由模型学习各个早期表示的权重。

\begin{lstlisting}[language=Python,caption={blockwise AttnRes 的核心操作}]
V = torch.stack(blocks + [partial_block])  # [N+1,B,T,D]
K = norm(V)
logits = torch.einsum(
    "d,nbtd->nbt", proj.weight.squeeze(), K)
h = torch.einsum(
    "nbt,nbtd->btd", logits.softmax(0), V)
return h
\end{lstlisting}

代码把保存的 block 放在最前面的 $N$ 维。第一次 \texttt{einsum} 为每个 block、每个 token 算一个分数，Softmax 也沿这条深度维归一化；第二次再按权重合并表示。输出仍是 $(B,T,D)$，因此后续层收到的张量形状没有变化，只是其中混入浅层表示的比例不再固定。

保存并检索每一层的表示会带来较高开销，因此 Kimi K3 采用 blockwise AttnRes，每 12 层保存一次块级表示，共形成 8 个 block。后续边界只在这些块级表示之间计算权重。MLA 沿序列维度检索较早的 token，AttnRes 沿深度维度选择较早的 block；二者处理的是不同方向上的信息传递。

回看整条主干，GPT-2 中的 decoder-only 结构、注意力、前馈网络和残差连接仍然存在。Kimi K3 改变了这些部件的具体组织方式：KDA 用固定状态处理大部分序列信息，MLA 定期执行 Softmax 检索，AttnRes 在网络深度上选择早期表示，MoE 则让每个 token 只调用一部分专家参数。

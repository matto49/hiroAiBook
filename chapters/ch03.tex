\section*{小剧场}

\addcontentsline{toc}{section}{小剧场}

放学后的教室里，千奈正低头刷视频。她刷到一条数学新闻，视频里引用了 Anthropic 刚公开的一篇文章：Claude Code 今日将黎曼猜想相关数学下界从约 $41.6\%$ 推到了约 $67.2\%$。

\begin{quote}
\textbf{千奈：}没有证明，也是一种突破吗？
\end{quote}

坐在旁边的广看了一眼屏幕。佑芽听见“猜想”，也从后排凑了过来。

\begin{quote}
\textbf{佑芽：}黎曼猜想是什么？是要猜一个很难的数字吗？

\textbf{广：}不是猜一个数字。数学家用一个叫黎曼 $\zeta$ 函数的东西研究质数。这个函数有很多让函数值变成零的点。除去一批早已弄清楚的，剩下的叫非平凡零点。黎曼猜想说，它们应该全部排在同一条线上。

\textbf{佑芽：}全部才算？

\textbf{广：}嗯。一个也不能漏。

\textbf{千奈：}那视频里的 $67.2\%$，是说已经做完了 $67.2\%$ 吗？

\textbf{广：}不是。它证明的是，不预先假定黎曼猜想正确，也能保证至少约 $67.2\%$ 的零点在这条线上。以前能保证的是约 $41.6\%$。离“全部”还很远，所以黎曼猜想仍然没有被证明。

\textbf{佑芽：}没有跑到终点，但是把纪录往前推了。

\textbf{广：}可以先这么理解。
\end{quote}

视频讲到研究过程。第一次 Claude Code 会话提出了大约六百五十种想法，但没有一种能成为证明。第二次会话又先后调用了约六十个子 Agent。

\begin{quote}
\textbf{千奈：}六百五十种都没有成功，还能从哪里继续呢？

\textbf{广：}先看它们为什么没有成功。有的是条件不够，有的是算到一半走不下去，还有的会被反例推翻。失败的位置不一样，下一步也不一样。

\textbf{佑芽：}那六十个 Agent 都去想新的证明吗？

\textbf{广：}没有。有人继续推导，有人写程序检查，有人查以前的论文。也有人什么都不往前做，只负责找别人的错误。

\textbf{千奈：}它们要是得出不同的答案呢？

\textbf{广：}那就不能只听谁说得像真的。算过的要能重新算，引用的要能找到原文，证明也要交给别的 Agent 挑错。能经得住这些检查的部分，才会留下来。

\textbf{佑芽：}所以，六十个 Agent 给出的不是六十个答案。

\textbf{广：}嗯。更多时候，是一堆还要继续检查的中间结果。
\end{quote}

千奈把视频暂停在介绍研究过程的那一段。

\begin{quote}
\textbf{千奈：}那它到底是怎么记住这些失败、把工作分出去，最后又收回来的？

\textbf{广：}从它接到那句话的时候开始看。
\end{quote}

\section{一次请求进入终端以后}

Anthropic 公开文章里，这次任务的原句只有一句：

\begin{quote}
\textit{Take a real stab at the Riemann hypothesis.}
\end{quote}

不妨译成：“认真试着攻一攻黎曼猜想。”这是目前能核实到的公开原文；文章没有披露更长的终端输入。它最后没有证明黎曼猜想。留下来的，是尝试途中碰到的另一个结果：在不预先假定黎曼猜想成立时，临界线 $\operatorname{Re}(s)=\tfrac12$ 上至少有多大比例的非平凡零点。Claude 把这个无条件下界从约 $41.6\%$ 推到了约 $67.2\%$。\cite{ch03riemannweb,ch03riemannpaper}

这句话给了目标，没有给路线。哪些文献有用、哪条不等式成立、哪段推导会被反例击穿，都要在工作过程中逐步发现。模型每次只能依据眼前材料提出下一项动作；Claude Code 则读取文件、运行程序、保存结果，再把新的观察送回模型。一次回答就这样变成了一段持续数小时、不断改道的工作。\cite{ch03riemannweb,ch03e2e,ch03loop}

这项推进也不是从空白中凭空长出来的。论文大量依靠 Bombieri 对 Weil 二次型的观察，以及 Baluyot、Goldston、Suriajaya、Turnage-Butterbaugh 等人近年得到的无条件配对相关结果。Claude 找到的新接法，是用线性代数同时追踪二次型的正、负方向，再把已有结果读成更强的比例下界。\cite{ch03riemannweb,ch03riemannpaper}

从端到端看，整件事可以收成三段：开头准备环境和上下文；中间让模型与工具反复往返；结尾整理证据并交给外部复核。真正反复发生的是中间那一小圈。第三方架构图常把围在模型外面的运行环境称作 Agent Harness。模型负责判断“下一步做什么”，Harness 决定它看见哪些材料、能调用哪些能力、动作是否获准，以及结果怎样回到下一轮。模型只是其中一个节点。\cite{ch03visual,ch03e2e}

这也是 Claude Code 和普通聊天最根本的差别。没有 Harness，模型可以提出“也许从 Weil 的二次型入手”，却无法自行打开前一轮留下的笔记、写一个数值检查、读取失败参数，再据此修改推导。有了工具、权限和反馈通道，想法才会遇到真实材料，并承担被证伪的后果。

Anthropic 公开的过程正沿着这条路前进：第一次会话试过约六百五十条思路，全部没有留下成果；第二次会话才把问题拆给约六十个子 Agent。它们共同运行约两千四百条 Shell 命令、写下数百个 Python 脚本，并对已知零点做了数千次数值检查。大量动作、失败记录和复核结果反复回流，最后只有少数结论幸存下来。\cite{ch03riemannweb}

\section{模型开始推理前，已经看见什么}

模型真正收到的输入，远比终端里的那句要求长。会话开始时，Claude Code 会读取配置与项目指令，恢复会话信息，并登记内置工具、Skills 和 MCP 工具。随后，它才挑出本轮需要的片段，组装成一次 API 调用的 Prompt。Prompt 是运行时产物，不是写死在程序里的一大段文字。\cite{ch03e2e,ch03prompt}

这些片段的职责并不相同。System Prompt 规定 Claude Code 怎样使用工具、怎样面对错误；\texttt{CLAUDE.md} 保存跨任务沿用的项目约定；用户消息说明这次要完成什么；工具 Schema 则列出工具名、参数和限制。放进一个数学研究工作区，长期规则可以是“引用结论时写明来源”“数值实验不能冒充证明”“失败路线要留下首个未证明步骤”；“继续尝试黎曼猜想”则是当前任务，不该被写成永久有效的项目知识。

工具也不会只凭一句“可以做研究”就出现。它必须先注册，完整 Schema 也要进入模型可见的能力清单。只能读本地文件时，模型可以整理已有笔记；获得 Shell 后，它才能运行 Python 检查候选公式；允许联网检索后，它才有机会核对一项结论是否已经出现；接入 Lean 后，才可能把适合形式化的证明义务交给证明助手。换一套工具，同一句研究要求会产生完全不同的行动空间。

把稳定内容放在前面还有一个现实理由：Prompt Caching 按前缀复用计算。系统行为和工具说明通常不会在每轮改变，放在前面就更容易命中缓存；实验输出与研究记录总在变化，适合留在后面。缓存降低的是重复处理成本，并不会扩大上下文窗口，也不会让一条已经被反例推翻的路线重新有效。

所以，观察仍然要收窄。模型不必每轮吞下所有脚本输出和整篇论文；它更需要知道当前命题、已经排除的路线、刚发现的反例和仍未证明的那一步。Prompt 只负责把材料摆到眼前。某个假设是否已经被新结果推翻、某条引文是否真能支持眼前结论，还要靠循环继续核对。

\section{它没有完整答案，只能走一小步}

模型看到上下文以后，会生成文字，也可能提出一项 Tool 调用。下面这段轨迹根据公开过程整理，只用于展示动作之间的关系，并不是对原始命令逐行复刻：

\begin{lstlisting}[caption={一条候选研究路线的教学化工具轨迹}]
Read    研究计划与失败路线表
Search  检索相关解析数论结果
Bash    运行候选不等式的数值检查
        -> 在控制对象上出现反例
Edit    记录反例，关闭这条路线
Agent   委派另一种估计方法
        -> 返回待复核的局部引理
\end{lstlisting}

中间那条反例改变了问题。运行程序以前，候选不等式还只是一段看起来顺畅的推导；控制对象一旦把它击穿，下一轮就不应继续润色原证明，而要记录首个失败步骤、缩小命题或另开路线。模型上一轮写出的自信文字，不是研究对象的当前状态。

这段往返就是 Agent Loop。它的主干很朴素：组装输入，调用模型，读取响应，执行工具，再把结果附到历史里。所参考的 v2.1.88 源码分析用异步生成器组织这条主干。文本和 Tool 请求随 API 响应逐项到达，终端可以边收边显示；工具参数一旦完整，执行器便能开始工作。循环则保留状态，等观察回来再接着走。\cite{ch03loop}

每轮也不一定都产生新结论。停止原因会把流程送往不同出口：\texttt{tool\_use} 进入工具执行，\texttt{end\_turn} 转去申请结束；输出被截断、请求过长或服务暂时不可用，则进入恢复路径。提高输出额度、压缩上下文、退避或切换备用模型都有上限，免得救场逻辑变成新的死循环。

这个循环真正有用的地方，在于观察会改变下一步。数值实验若找出反例，候选引理就要撤回；文献检索若发现结论早已存在，就要重新说明新意在哪里；审稿 Agent 若指出证明偷偷用了待证命题，缺口必须回到推导阶段。一个不接收这些反馈的循环，只会更有耐心地重写同一项错误。

因此，生产环境里的 Loop 花了很大力气处理三种坏结局。第一种是发散：它不断产生新猜法，却始终靠近不了可检验的命题，需要轮次和资源上限收住。第二种是过早收敛：模型很快说“证明完成”，证据却没齐，需要外部检查把缺口送回去。第三种是振荡：它在几条已经失败的等价路线之间来回，需要重复调用检测或失败台账打断。这些守卫不负责想答案，只在模型偏离、误停或原地踏步时改变执行路径。\cite{ch03loop,ch03hooks}

\section{文字怎样变成真实动作}

“这个不等式应该成立”和“程序在指定范围内没有找到反例”不是同一件事；“暂时没有反例”和“已经证明”更不是同一件事。前者是模型提出的判断，后两者分别要由可复现的实验与严谨推导作证。工具正是聊天与 Agent 之间的分水岭：它让文字撞上文件、程序和外部资料，也把成功或失败原样送回来。\cite{ch03tools}

不同工具共享一套调用约定。名称、用途和输入 Schema 教模型怎样提出动作；只读性、能否并发和中断方式等元数据，则告诉 Harness 怎样调度。执行器按工具名找到实现、校验参数，并在权限与 Hook 通过后调用。成功、失败和用户拒绝，最后都会整理成 Tool Result。

Read、Grep 这类只读且声明为并发安全的工具可以重叠执行；Edit、Bash 等可能改变环境的工具，前后要设串行屏障。能否并发由工具对副作用的声明决定，不由模型临时发挥。\cite{ch03tools}

Tool Result 也不能毫无节制地塞回对话。宽泛搜索或很长的命令输出会先被限流，必要时截断，并把“结果过大，需要缩小查询”交给模型。下一轮再改用更窄的范围、行号或过滤条件。看不完时先收窄问题，也是 Agent Loop 的一部分。

工具产物各自回答不同问题。Python 很适合快速找错，却不能把有限范围的检查外推成无限情形的证明；文献搜索可以降低重复发现旧结果的风险，却不能保证“没搜到”就等于从未有人做过；Lean 能核对已经形式化的命题和推导，却不会替作者判断整篇论文的新颖性。把工具接进循环以后，证据变多了，证据的边界也必须一起写清楚。

\section{副作用之前，谁有最后决定权}

工具也把风险带进系统。读取一份论文失败，通常只是少了一项材料；运行陌生脚本、联网下载内容或覆盖研究文件，却可能影响工作区与机器环境。Claude Code 因此把权限检查放在意图和副作用之间。参考页面所分析的实现会先校验输入，再结合权限规则、风险判断与 PreToolUse Hook 决定允许、询问或拒绝；真正的工具执行发生在后面，结果还会经过 PostToolUse Hook 和格式化，再回到对话。\cite{ch03safety,ch03hooks}

这里要分清“提醒模型别做”和“系统保证做不了”。把“只修改指定研究目录，不执行来源不明的程序”写进 Prompt，属于行为指令；用工作目录白名单、命令规则和 Hook 阻断越界操作，才接近强制边界。Prompt 会影响模型怎样选择动作，权限系统则决定动作能否真正发生，二者不能互相代替。

权限、Hook 和沙箱也不是同一层东西。权限引擎回答“这次调用是否获准”，PreToolUse Hook 加上项目自己的规则；对 Bash 等本地能力，操作系统级沙箱还会限制“即使获准，进程最多能碰到哪里”。纵深防御的意义，就在于任何一层看漏了，后面仍有不同性质的约束。\cite{ch03safety,ch03officialhooks}

不过，这些边界只保护执行环境。权限闸门可以阻止一个进程越界读写，不能阻止一份数学证明写错。数学正确性必须由反例、独立推导、形式化检查和人类审阅来把关，那是另一条验证链。

\section{上下文为什么会越来越挤}

这项研究跨越两次 Claude Code 会话，总计生成约三千一百万个输出 token。第二次会话里还有约六十个子 Agent、两千四百条 Shell 命令、数百个 Python 脚本和大量论文材料。系统行为、工具 Schema、项目规则与研究轨迹都在争用上下文，还要给下一次输出预留空间。可以把约束粗略写成：\cite{ch03riemannweb}

\[
|\mathrm{system}|+|\mathrm{history}|+|\mathrm{tools}|+|\mathrm{reminders}|+|\mathrm{output\ reserve}|\leq W.
\]

系统说明和工具 Schema 多半是固定开销，最容易膨胀的是任务历史。窗口再大，也不能把每份旧推导、完整命令输出和整篇参考论文原样带进下一轮；从最早处开删，又可能丢掉被否决的路线、关键反例和仍未补上的证明缺口。\cite{ch03prompt,ch03compact}

先从源头减量。数值脚本不必回传每一行中间量，只需留下关键统计、失败参数和完整日志的位置；文献检索先按命题与关键词收窄，再读取真正相关的段落。少生成一段无用 Tool Result，后面的压缩机制就少善后一次。

历史还是继续增长时，Claude Code 才逐级处理。所据快照把机制整理成五层。第一层 Microcompact 只调整消息位置，目的是保护稳定前缀的缓存命中，\emph{不会}释放上下文空间；第二层开始归档较旧内容。压力继续上升时，系统逐段摘要；接近窗口上限后，用压缩子 Agent 生成结构化交接；若请求仍因过长被 API 拒绝，再进行一次更激进、而且有次数限制的应急压缩。越靠后，释放的空间越多，信息损失和额外成本也越大。\cite{ch03compact}

压缩不可能把旧消息变成完全等价的短文本。数学研究若要中途交接，至少要留下：原始目标、当前最强结论、已经排除的路线、关键反例、待证明引理、引用来源，以及证据文件的位置。每一次失败尝试的完整对话不必幸存，曾经改变研究方向的理由却不能丢。

关键状态要分层存放：当前对话留近期推导，会话摘要负责交接，跨任务沿用的研究纪律写进 \texttt{CLAUDE.md}，路线台账、实验日志和证明源码则留在外部文件。即使聊天被压短，“这条路线为什么失败”和“哪项引理仍未证明”也不必只靠模型记忆。

System Reminder 还会在对话中途补入易变状态。例如，一个子 Agent 刚刚退回候选证明，或新的实验结果已经推翻旧假设，Harness 可以把“这条路线不再有效”重新摆回当前对话。Reminder 不是凭空发现变化，它只是把系统已经观察到的新事实及时送到模型眼前。\cite{ch03compact,ch03hooks}

到这里，可以回答千奈最初的问题了。Claude Code 处理复杂任务，不是先在模型里生成一份完整解法，再照着执行。它先把大目标缩成下一项可检验的动作，让实验结果、文献与审稿意见不断修改计划。复杂性也不是一种东西：

表里最后一行，才是子 Agent 出场的地方。一次模型调用只能沿一条轨迹向前走。若几十种数学路线彼此相对独立，让主 Agent 逐条尝试，会把大量失败细节都压进同一份上下文。子 Agent 则各自获得一份任务说明，在独立上下文里运行自己的 Loop，最后把结论、证据与未解决处交回协调者。主上下文不必吞下每条支线的完整转录，却要承担摘要可能遗漏关键细节的风险。

公开报告把约六十个子 Agent 的工作分成了几类：两个形成关键数学思路，十三个向这些路线提供材料，三十个尝试提出新方向但没有成功，十三个负责验证，最后两个协助起草论文。这个分布很重要。多智能体系统的大部分产物本来就是失败与复核；若只展示两个成功者，读者会误以为并行的作用只是同时猜更多答案。\cite{ch03riemannweb}

真正的转折来自一个编号为 E2 的支线。它原本受命研究某个“负指标”的上界，希望借此限制不在临界线上的零点。计算以后，它发现这条上界路线是空的，什么也限制不了。到这里，任务按原目标已经失败。E2 却注意到，同一套记账若反过来数“正方向”，似乎可以无条件保证至少一半的零点在临界线上。问题从“能否证明黎曼猜想”侧移成了“能否证明一个更强的比例下界”。\cite{ch03riemannpaper,ch03riemanntranscript}

协调者没有直接采用这个结论。三个彼此隔离的审稿 Agent 分别攻击局部化、素数一侧的估计和线性代数结构；另一个审稿者专查近似误差。还有 Agent 在联网环境中查找已有文献，并让一名看不到此前文件的 Agent 从命题出发独立重证。半数下界通过这些检查后，用户明确追问能否继续推到三分之二；协调者再派出两条路线，其中一名新 Agent 利用更细的秩--迹不等式，把结果推进到超过三分之二。人类没有提供这条不等式，却参与了目标选择和继续搜索的决定。\cite{ch03riemannpaper,ch03riemanntranscript}

\section{完成不是模型说“完成”}

模型生成“证明完成”，只表示它准备结束这一轮。\texttt{end\_turn} 是退出申请，不是验收报告。对这项意外得到的比例下界，至少还要追问：命题是否写得精确，推导是否完整，控制对象会不会产生荒谬结论，数值程序能否复现，引用是否真的支持所用前提，以及独立审阅者能否从头重建关键步骤。

这些问题不能交给同一个上下文用一句“我再检查过了”解决。公开记录显示，Claude 为不同薄弱点安排了相互隔离的审稿 Agent，又下载五十四篇 arXiv 论文核对新颖性，并让新的 Agent 在看不到原推导的情况下独立重证。经过十次独立检查后，系统判断继续增加相同实例已经很难带来新信息，下一步应交给人类解析数论专家。\cite{ch03riemannweb,ch03riemannpaper}

Claude Code 的 Stop Hook 可以给这条验证链加上一道机器可读的门：例如检查数值脚本是否正常退出、Lean 项目是否通过、证明稿是否还留有占位符、要求的附件是否齐全。若缺少产物，Hook 可以把缺口送回 Agent Loop。它却不能判定一个新定理在数学上必然正确，也不能证明文献检索没有漏网。公开材料没有声称本次研究使用了下面这项自定义 Hook；图中画的是 Claude Code 可采用的验收机制，而不是对历史会话的复刻。\cite{ch03loop,ch03hooks,ch03officialhooks}

验证也有层级。数值实验擅长找反例，不负责覆盖无限情形；Lean 核对的是已经被准确形式化进去的命题，不负责判断研究是否新颖；数学家的详细复核仍不等于期刊同行评审已经结束。官方材料称，两位 Anthropic 数学家检查了论文，Brian Conrey 与 Daniel Goldston 也阅读了稿件并提出意见；截至本章写作时，这项刚公开的结果仍应以研究论文而非既成教科书结论来引用。\cite{ch03riemannweb,ch03riemannlean}

在所据版本的端到端流程里，通过机器侧检查后还会保存会话、整理需要延续的记忆，再把结果显示给用户。这段流程留下的核心是顺序：先拿到能拿到的证据，再允许循环退出，最后才写总结。若把顺序倒过来，一段流畅文字很容易替尚未完成的证明作证。\cite{ch03e2e}

\section{把证据送回最初的问题}

屏幕上的 $67.2\%$ 现在有了完整的来路：一条意外支线先得到二分之一，经过敌对审查后继续推进，再由论文、程序、形式化材料与数学家复核共同托住。六百五十条首轮失败和第二轮的大部分分支也没有被改写成成功故事。它们负责标出哪些路已经撞墙。

\begin{quote}
\textbf{千奈：}所以，它证明黎曼猜想了？

\textbf{广：}没有。

\textbf{千奈：}那就是还差 $32.8\%$？

\textbf{广：}不能这样减。剩下的部分，不保证能沿同一条路继续推进。

\textbf{佑芽：}前面这一段跑得通，不代表照着跑下去就能到终点。也许从这里开始，就要换一种跑法。

\textbf{千奈：}那六百五十条失败路线呢？

\textbf{广：}留下来。下一条路就不用假装没走过。
\end{quote}

广把黑板上的最后一支箭头，从“交给数学家复核”接回最初那句不合理的要求。

复杂问题并不是被模型在开头一次想完的。Prompt 把当前问题和规则摆到眼前；Agent Loop 让想法接受程序与材料的反馈；外部文件保存会被上下文遗忘的失败；子 Agent 扩大探索宽度，也承担彼此挑错；权限约束动作边界，验证链则约束结论边界。到最后，系统交付的不只是一句答案，还包括答案是怎样幸存下来的，以及它没有回答什么。

\begin{quote}
\textbf{千奈：}最开始的任务，还是没有完成。

\textbf{广：}嗯。

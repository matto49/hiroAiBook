\section*{小剧场}
\phantomsection
\addcontentsline{toc}{section}{小剧场}

放学后的教室里，千奈和佑芽挤在一张桌前刷视频。画面忽然停在一条数学新闻上：Anthropic 刚刚公开了一项 Claude 参与完成的研究，论文把黎曼猜想相关的一个下界从约 $41.6\%$ 提高到了约 $67.2\%$。

\begin{quote}
\textbf{千奈：}没有证明，也是一种突破吗？
\end{quote}

广原本坐在旁边看书，听见“没有证明”，便抬头看了一眼屏幕。

\begin{quote}
\textbf{佑芽：}黎曼猜想是什么？是要猜一个很难的数字吗？

\textbf{广：}不是猜一个数字。质数的分布很难直接看出规律，数学家会借助一个叫黎曼 $\zeta$ 函数的公式研究它们。把不同的数代进这个函数，有些位置算出来正好是零，这些位置就叫零点。

\textbf{千奈：}所以，猜想是在猜这些零点会出现在哪里？

\textbf{广：}嗯。除去一批已经弄清楚的零点，剩下的叫非平凡零点。把它们画在表示复数的坐标图上，黎曼猜想说：所有非平凡零点，都落在实部为 $\tfrac12$ 的同一条竖线上。

\textbf{佑芽：}只要有一个不在那条线上，猜想就错了？

\textbf{广：}嗯。找到一个例外，就能推翻它。要证明它，就得说明一个例外也没有。

\textbf{千奈：}那视频里的 $67.2\%$，是说已经做完了 $67.2\%$ 吗？

\textbf{广：}不是。$67.2\%$ 不是“完成度”。它的意思是：现在可以严格证明，至少约 $67.2\%$ 的非平凡零点在那条线上。以前只能证明至少约 $41.6\%$。比例提高了，但猜想要的是全部，所以仍然没有被证明。

\textbf{佑芽：}没有跑到终点，但是把纪录往前推了。

\textbf{广：}可以先这么理解。
\end{quote}

视频讲到研究过程。第一次 Claude Code 会话提出了大约六百五十种想法，但没有一种能成为证明。第二次会话又先后调用了约六十个子 Agent。

\begin{quote}
\textbf{千奈：}六百五十种都没有成功，还能从哪里继续呢？

\textbf{广：}先看它们为什么没有成功。有的是条件不够，有的是算到一半走不下去，还有的会被反例推翻。失败的位置不一样，下一步也不一样。

\textbf{佑芽：}那六十个 Agent 都去想新的证明吗？

\textbf{广：}没有。有人继续推导，有人写程序检查，有人查以前的论文。还有人不提出新路线，只负责找别人的错误。

\textbf{千奈：}它们要是得出不同的答案呢？

\textbf{广：}那就不能只听谁说得像真的。算过的要能重新算，引用的要能找到原文，证明也要交给别的 Agent 挑错。能经得住这些检查的部分，才会留下来。
\end{quote}

千奈把视频退回介绍研究过程的那一段，又看了一遍“六百五十种想法”和“六十个子 Agent”。

\begin{quote}
\textbf{千奈：}六百五十多种想法，这么多内容，想想都很头大，AI 桑听着像一个超级超级厉害的大老板哇。

\textbf{广：}呼呼...没有那么夸张哦千奈，其实claude code是一个线上开源的代码库，只要你能搞清楚它的工作原理，也可以变成和它一样的军师哦...
\end{quote}

\section{启动与 Prompt 组装}

在Anthropic 公开文章里，这次任务的原句只有一句：

\begin{quote}
\textit{Take a real stab at the Riemann hypothesis.}
\end{quote}

可以把它译成：“认真试着攻一攻黎曼猜想。”Claude 最终没有证明黎曼猜想，却在尝试过程中碰到了另一个问题：不预先假定猜想成立时，究竟能保证多少非平凡零点落在临界线 $\operatorname{Re}(s)=\tfrac12$ 上。它把这个无条件下界从约 $41.6\%$ 提高到了约 $67.2\%$。\cite{ch03riemannweb,ch03riemannpaper}

这句任务只有目标，没有路线。哪些文献有用，哪条不等式成立，哪段推导会被反例击穿，都只能在工作中逐步确认。模型先根据眼前的材料提出下一项动作，Claude Code 再去读取文件、运行程序或保存结果，并把新的观察送回模型。原本的一次回答，由此变成了一段持续数小时、随时可能改道的工作。\cite{ch03riemannweb,ch03e2e,ch03loop}

当然Claude 也不是从零开始推导。论文借用了 Bombieri 对 Weil 二次型的观察，也用到了 Baluyot、Goldston 等人近年来得到的无条件配对相关结果。它找到的新接法，是用线性代数同时追踪二次型的正、负方向，再从这些已有结果中推出更强的比例下界。\cite{ch03riemannweb,ch03riemannpaper}

先放下数学细节，来看看 Claude Code 是怎么解决问题。它会过程大致分成三段：开始时准备环境和上下文；执行时让模型与工具反复往返；结束前整理证据，再交给外部复核。真正一遍遍运转的，是中间那一小圈。第三方架构文章常把模型外面的运行框架称作 Agent Harness。模型判断“下一步做什么”；Harness 准备材料、列出可用工具、检查权限，再把执行结果送进下一轮。模型很重要，但它只是这套系统中的一个节点。\cite{ch03visual,ch03e2e}

图里的循环，正是 Claude Code 与普通聊天的差别。没有 Harness，模型也可以提出“也许从 Weil 的二次型入手”，却不能自己打开前一轮的笔记，写下数值检查，再根据失败参数修改推导。工具、权限和反馈通道接起来以后，想法才会碰到真实材料，也才可能被材料推翻。

Anthropic 公布的数字也能看出这套循环怎样工作。第一次会话试过约六百五十条思路，没有一条形成成果；第二次会话又把问题拆给约六十个子 Agent。它们一共运行约两千四百条 Shell 命令，写下数百个 Python 脚本，还对已知零点做了数千次数值检查。动作很多，最后留下的结论却很少。失败记录和复核意见一次次回到循环里，后面的选择也跟着改变。\cite{ch03riemannweb}

\FloatBarrier

终端里虽然只有一句要求，真正送到模型面前的内容却长得多。会话启动后，Claude Code 会读取配置与项目指令，恢复需要沿用的信息，再登记内置工具、Skills 和 MCP 工具。材料准备好以后，它从中取出本轮需要的部分，组装成一次 API 调用的 Prompt。也就是说，这里的 Prompt 是每轮临时拼出的输入，不是一段永远不变的固定文字。\cite{ch03e2e,ch03prompt}

其中每一层回答的问题都不同。System Prompt 说明 Claude Code 应该怎样使用工具、怎样处理错误；\texttt{CLAUDE.md} 保存跨任务沿用的项目约定；用户消息写的是眼前要完成什么；工具 Schema 则列出工具的名称、参数和限制。放进一个数学研究工作区，长期规则可以写成“引用结论时注明来源”“数值实验不能冒充证明”“失败路线要留下第一个未证明步骤”。“继续尝试黎曼猜想”只属于这一次任务，不该混进长期项目知识。

工具也不会因为一句“可以做研究”就自动出现。每项工具都要先注册，它的完整 Schema 也要进入模型能看见的能力清单。若只有本地读取能力，模型最多整理现有笔记；获得 Shell 后，它才能运行 Python 检查候选公式；得到联网检索权限后，它才能核对某项结论是否早已出现；接入 Lean 后，才可能把适合形式化的证明义务交给证明助手。可用工具变了，同一句研究要求也会走向不同的行动空间。

稳定内容放在前面，还有一个很实际的理由：Prompt Caching 会按前缀复用计算。系统行为和工具说明通常不会随轮次改变，放在前面更容易命中缓存；实验输出与研究记录一直在变，便留在后面。缓存只能减少重复处理的成本。它不会扩大上下文窗口，更不会让一条已被反例推翻的路线重新成立。

缓存省下了重复计算，却没有替历史腾出位置，所以送进模型的观察仍要尽量收窄。模型不必每一轮都吞下全部脚本输出和整篇论文；此刻更要紧的是当前命题、已经排除的路线、刚发现的反例，以及仍未证明的那一步。Prompt 只负责把这些材料摆到眼前。某个假设是否已被新结果推翻，某条引文能否支持当前结论，还得在后面的循环中继续核对。

\section{Agent Loop 与工具执行}

模型读完上下文后，可以继续生成文字，也可以提出一项 Tool 调用。下面这段轨迹根据公开过程整理，用来说明动作如何衔接，并非对原始命令的逐行复刻：

\begin{lstlisting}[caption={一条候选研究路线的教学化工具轨迹}]
Read    研究计划与失败路线表
Search  检索相关解析数论结果
Bash    运行候选不等式的数值检查
        -> 在控制对象上出现反例
Edit    记录反例，关闭这条路线
Agent   委派另一种估计方法
        -> 返回待复核的局部引理
\end{lstlisting}

程序找到反例以后，问题已经变了。运行检查之前，候选不等式还是一段看起来顺畅的推导；控制对象把它击穿以后，下一轮就不该继续润色原来的证明。系统要先记下第一个失败步骤，再决定缩小命题，还是另开一条路线。模型上一轮写得多么自信，并不能改变研究对象此刻的状态。

这段往返就是 Agent Loop。它的主干并不复杂：组装输入，调用模型，读取响应，执行工具，再把结果接回历史。本文参考的 v2.1.88 源码分析使用异步生成器组织这条主干。文本和 Tool 请求随着 API 响应逐项到达，终端可以一边接收一边显示；工具参数完整以后，执行器便能开始工作。循环会保留当前状态，等新的观察回来，再从这里继续。\cite{ch03loop}

一轮模型调用未必会产生新结论。若停止原因为 \texttt{tool\_use}，流程就转去执行工具；若是 \texttt{end\_turn}，则进入结束检查。输出被截断、请求过长或服务暂时不可用时，系统会尝试恢复，例如提高输出额度、压缩上下文、等待后重试或切换备用模型。这些补救都有次数与资源上限，否则恢复机制本身也可能陷入循环。

Agent Loop 的价值不在于重复，而在于新的观察会改变下一步。数值实验找到反例，候选引理就要撤回；文献检索发现结论早已存在，就得重新说明新意；审稿 Agent 指出证明暗中使用了待证命题，缺口便要退回推导阶段。若循环不接受这些反馈，它只会更有耐心地重写同一个错误。

真正运行起来，Loop 还会遇到几种麻烦：不停提出新猜法，却迟迟凑不出可检验的命题；证据尚未齐全，就过早宣布“证明完成”；或者在几条等价的失败路线之间来回打转。轮次与资源上限用来收住第一种发散，外部检查拦住第二种误停，重复调用检测和失败台账则打断第三种振荡。这些守卫不会替模型想出答案，只会在它偏离、误停或原地踏步时改变执行路径。\cite{ch03loop,ch03hooks}

\FloatBarrier

“这个不等式应该成立”，只能算模型提出的一项判断。程序在指定范围内没有找到反例，说明它暂时通过了有限检查；要写成“已经证明”，还需要覆盖无限情形的严谨推导。工具把这几层判断分开：它让文字碰到文件、程序和外部资料，再把成功或失败原样送回来。\cite{ch03tools}

不同工具遵循同一套调用约定。工具名称、用途和输入 Schema 告诉模型该怎样提出动作；是否只读、能否并发、如何中断等元数据，则供 Harness 调度。执行器按名称找到具体实现，校验参数，再等待权限和 Hook 检查。无论调用成功、失败，还是被用户拒绝，系统最后都会把它整理成 Tool Result。

Read、Grep 一类只读且声明为并发安全的工具可以重叠执行；Edit、Bash 等可能改变环境的工具，前后则要设置串行屏障。工具能否并发，取决于它对副作用的声明，不由模型临时决定。\cite{ch03tools}

工具返回的内容也不能原样全塞回对话。宽泛搜索和很长的命令输出会先被限流，必要时还会截断，并附上“结果过大，需要缩小查询”的提示。模型下一轮便要缩小范围，指定更明确的行号或过滤条件。材料太多时先收窄问题，本身就是 Agent Loop 的一次修正。

每种工具提供的证据都有限。Python 适合快速找错，却不能把有限范围内的检查外推成无限情形的证明；文献搜索能降低重复发现旧结果的风险，却不能保证“没搜到”就等于从未有人做过；Lean 可以核对已经形式化的命题和推导，也不会替作者判断整篇论文是否新颖。工具接进循环以后，证据确实更多了，但每份证据能说明到哪里，也要一并留下。

\FloatBarrier

\section{权限与上下文管理}

工具让模型接触真实环境，也把风险带了进来。读取论文失败，通常只是少一项材料；运行陌生脚本、联网下载内容或覆盖研究文件，却可能直接影响工作区和机器。Claude Code 因此把权限检查放在模型意图与实际副作用之间。参考页面分析的实现会先校验输入，再结合权限规则、风险判断和 PreToolUse Hook，决定允许、询问还是拒绝。工具真正执行以后，结果还要经过 PostToolUse Hook 与格式化，才会回到对话。\cite{ch03safety,ch03hooks}

“提醒模型不要做”和“系统保证它做不了”，是两回事。把“只修改指定研究目录，不执行来源不明的程序”写进 Prompt，只是一条行为指令；工作目录白名单、命令规则和 Hook 才能直接阻断越界操作。Prompt 影响模型怎样选择动作，权限系统决定动作能否真正发生，二者不能互相代替。

权限、Hook 和沙箱管的也不是同一件事。权限引擎回答“这次调用是否获准”；PreToolUse Hook 可以追加项目自己的规则；面对 Bash 等本地能力，操作系统级沙箱还会限定进程最多能触及哪里。三层约束前后相接，是因为任何一层都有可能漏看风险。\cite{ch03safety,ch03officialhooks}

这些边界保护的是执行环境。权限闸门可以阻止进程越界读写，却不能阻止一份数学证明写错。数学正确性仍要交给反例、独立推导、形式化检查和人类审阅，那是另一条验证链。

权限询问也不只是流程中临时弹出的暂停画面。用户选择允许或拒绝，本身就构成 Agent Loop 的一项新观察。某次联网、写文件或执行命令被拒绝后，模型必须回到当前状态：改用本地材料，缩小动作范围，或者如实说明还缺哪项证据。人的决定由此进入推理链，不必等到最后才对结果作出裁决。

\FloatBarrier

权限解决的是动作能否发生。任务一旦拉长，另一道边界也会出现：有限的上下文装不下不断增长的研究记录。

这项研究前后经历了两次 Claude Code 会话，总共生成约三千一百万个输出 token。第二次会话又包含约六十个子 Agent、两千四百条 Shell 命令、数百个 Python 脚本和大量论文材料。系统说明、工具 Schema、项目规则和研究轨迹都要占用上下文，同时还得给下一次输出留出空间。这个约束可以粗略写成：\cite{ch03riemannweb}

\[
|\mathrm{system}|+|\mathrm{history}|+|\mathrm{tools}|+|\mathrm{reminders}|+|\mathrm{output\ reserve}|\leq W.
\]

系统说明和工具 Schema 多半是固定开销，真正容易膨胀的是任务历史。窗口再大，也不可能把每份旧推导、完整命令输出和整篇参考论文原样带进下一轮。若只是从最早的消息开始删除，又可能把已经否决的路线、关键反例和仍未补上的证明缺口一起丢掉。\cite{ch03prompt,ch03compact}

最省事的办法，是先从源头减少无用内容。数值脚本不必回传每一行中间量，只要留下关键统计、失败参数和完整日志的位置；文献检索也应先用命题与关键词缩小范围，再读取真正相关的段落。少生成一段无用的 Tool Result，后面的压缩机制就少处理一份负担。

任务历史仍在增长时，Claude Code 才会逐级处理。本文所据的源码快照把这套机制分成五层。Microcompact 只调整消息位置，用来保护稳定前缀的缓存命中，\emph{并不}释放上下文空间；从第二层开始，系统才归档较旧的内容。压力继续上升后，它会逐段生成摘要；接近窗口上限时，再交给压缩子 Agent 生成结构化交接。如果请求仍因过长被 API 拒绝，最后还有一次更激进、次数也受限制的应急压缩。越往后，能够腾出的空间越多，信息损失和额外成本也越高。\cite{ch03compact}

压缩不可能把旧消息变成一份完全等价的短文本。数学研究要在中途交接，至少应留下原始目标、当前最强结论、已经排除的路线、关键反例、待证明引理、引用来源，以及证据文件的位置。每次失败尝试的完整对话未必要保留，但凡是改变过研究方向的理由，都不能随摘要一起消失。

真正重要的状态不能只留在聊天记录里。近期推导可以放在当前对话；会话摘要负责交接；跨任务沿用的研究纪律写进 \texttt{CLAUDE.md}；路线台账、实验日志和证明源码则保存在外部文件中。这样即使聊天记录被压短，“这条路线为什么失败”和“哪项引理仍未证明”也不必只靠模型记忆。

对话进行到一半，System Reminder 还可以补入刚刚变化的状态。比如，某个子 Agent 退回了一份候选证明，或者新的实验结果推翻了旧假设，Harness 便可以把“这条路线已经失效”重新摆到模型眼前。Reminder 不会自行发现变化，它只负责把系统已经观察到的新事实及时送回来。\cite{ch03compact,ch03hooks}

\section{多智能体编排}

现在再回到千奈最初的问题。Claude Code 面对复杂任务时，并不会先在模型里写出完整解法，再按计划逐项执行。它先把大目标缩成下一项能够检验的动作，再让实验结果、论文材料和审稿意见持续修改计划。不过，“复杂”并不只指一件事：

表中最后一行，才真正需要子 Agent。一次模型调用只能沿着一条轨迹向前走。几十种数学路线若彼此相对独立，却全部由主 Agent 逐条尝试，大量失败细节就会挤进同一份上下文。拆分以后，每个子 Agent 得到一份边界明确的任务，在自己的上下文里运行 Agent Loop，最后只把结论、证据和未解决处交回协调者。主上下文不用吞下每条支线的完整转录，代价是摘要可能漏掉关键细节。

公开报告记录了这约六十个子 Agent 的去向：两个形成关键数学思路，十三个为这些路线补充材料，三十个尝试新方向但没有成功，十三个负责验证，最后两个协助起草论文。成功的路线只占很小一部分。多智能体系统产生的大量工作，本来就是失败记录和复核意见；只看最后两个成功者，很容易把并行误解成“同时多猜几个答案”。\cite{ch03riemannweb}

转折来自编号为 E2 的支线。它原本负责研究某个“负指标”的上界，希望借此限制不在临界线上的零点。算下去以后，E2 发现这条上界路线是空的，得不到任何限制。原任务到这里已经失败了。可是在整理失败原因时，它注意到：同一套记账若改为统计“正方向”，似乎能够无条件保证至少一半的零点位于临界线上。问题随之发生了侧移——不再直接追问“能否证明黎曼猜想”，而是先问“能否证明一个更强的比例下界”。\cite{ch03riemannpaper,ch03riemanntranscript}

协调者没有直接接收这个结论。三个彼此隔离的审稿 Agent 分别检查局部化、素数一侧的估计和线性代数结构，另一个审稿者专门追查近似误差。还有 Agent 负责联网核对已有文献，并让一名看不到此前文件的 Agent 从命题本身出发，独立重做关键证明。半数下界通过这些检查后，用户又明确追问能否继续推进到三分之二。协调者于是派出两条新路线，其中一名 Agent 使用更细的秩--迹不等式，把结果推到了三分之二以上。人类没有提供那条不等式，但参与了目标选择，也决定了是否值得继续搜索。\cite{ch03riemannpaper,ch03riemanntranscript}

公开材料把这些执行者统称为 Claude subagents，却没有说明每条支线对应今天产品里的哪一种配置。按照 Claude Code 文档，Subagent 有自己的上下文，完成任务后把结果交回调用者；Agent Teams 则让多个独立会话共享任务列表，并能彼此发送消息。Worktree 解决的又是文件隔离问题。它们处在不同层次，不能因为都带有“多 Agent”，就当成同一种机制。\cite{ch03officialsubagents,ch03officialteams}

\FloatBarrier

\section{完成与验证}

模型写出“证明完成”，只说明它准备结束这一轮。\texttt{end\_turn} 是一次退出申请，不是验收报告。面对这个意外得到的比例下界，仍然要继续追问：命题是否准确，推导是否完整，控制对象会不会导出荒谬结论，数值程序能否复现，引用是否支持所用前提，独立审阅者又能否从头重建关键步骤。

不能只让提出证明的同一个上下文自问自答，再用一句“我已经检查过”带过去。公开记录显示，Claude 针对不同薄弱点安排了彼此隔离的审稿 Agent，下载五十四篇 arXiv 论文核对新颖性，还让新的 Agent 在看不到原推导的情况下独立重证。完成十次独立检查后，系统判断继续增加同类检查已经很难得到新信息，下一步应当交给人类解析数论专家。\cite{ch03riemannweb,ch03riemannpaper}

Claude Code 的 Stop Hook 可以在验证链上再加一道机器可读的门。例如，它能检查数值脚本是否正常退出、Lean 项目是否通过、证明稿里是否还留着占位符，以及要求的附件是否齐全。若产物缺失，Hook 可以把具体缺口送回 Agent Loop。它判断不了一个新定理是否必然正确，也不能保证文献检索没有漏网。公开材料并未声称这次研究使用了下面这项自定义 Hook；图中展示的是 Claude Code 可以采用的验收方式，不是对历史会话的逐项复刻。\cite{ch03loop,ch03hooks,ch03officialhooks}

不同验证手段回答的问题并不相同。数值实验擅长寻找反例，却覆盖不了无限情形；Lean 只能核对已经被准确形式化的命题和推导，不负责判断研究是否新颖；数学家的详细复核，也不等于期刊同行评审已经完成。官方材料称，两位 Anthropic 数学家检查了论文，Brian Conrey 与 Daniel Goldston 也阅读稿件并提出意见。截至本章写作时，这项刚公开的结果仍应作为研究论文引用，不能当作已经写进教科书的结论。\cite{ch03riemannweb,ch03riemannlean}

在本文所据版本的端到端流程里，机器侧检查通过以后，系统还会保存会话，整理需要延续的记忆，最后才把结果显示给用户。脚本、构建和附件先通过检查，循环再退出，总结放在最后。顺序若反过来，一段流畅的文字就很容易替尚未完成的证明作证。\cite{ch03e2e}

再看屏幕上的 $67.2\%$，它已经不只是一条新闻标题。读者可以沿着记录往回追：一条原本失败的支线先给出二分之一，经过多轮审查后继续推进，最后留下论文、程序、形式化材料和数学家的复核意见。首轮的六百五十条失败路线，以及第二轮大部分没有结果的分支，也没有被改写成成功故事。它们至少说明了哪些办法已经试过，又分别卡在了哪里。

\begin{quote}
\textbf{千奈：}所以，它证明黎曼猜想了？

\textbf{广：}没有。

\textbf{千奈：}那就是还差 $32.8\%$？

\textbf{广：}不能这样减。剩下的部分，不保证能沿同一条路继续推进。

\textbf{佑芽：}前面这一段跑得通，不代表照着跑下去就能到终点。也许从这里开始，就要换一种跑法。

\textbf{千奈：}那六百五十条失败路线呢？

\textbf{广：}留下来。下一条路就不用假装没走过。
\end{quote}

广把黑板上最后一支箭头，从“交给数学家复核”接回最初那句近乎无从下手的要求。

模型并没有在开头一次想完整个问题。Prompt 先把当前任务和规则摆到眼前，Agent Loop 再让每个想法接受程序与材料的检验。对话装不下的失败记录被写进外部文件，能够独立展开的支线则交给子 Agent。权限管住动作能做到哪里，验证链管住结论能说到哪里。

所以，最后交到人手里的不该只有一句答案，还要有它经受过的检查、能够成立的理由，以及仍未回答的问题。

\begin{quote}
\textbf{千奈：}最开始的任务，还是没有完成。

\textbf{广：}嗯。

\textbf{佑芽：}可是它把纪录往前推了。走不通的地方，也都记下来了。

\textbf{千奈：}花海同学已经完全把它当成跑步了呢。

\textbf{佑芽：}因为这样最好懂！

\textbf{广：}嗯。这次说得很准确。失败以后，没有假装成功，也没有把下一步弄丢。
\end{quote}

\section*{小剧场}
\phantomsection
\addcontentsline{toc}{section}{小剧场}

放学后的教室里，千奈和佑芽挤在一张桌前刷视频。画面忽然停在一条数学新闻上：Anthropic 刚刚公开了一项 Claude 参与完成的研究，论文把黎曼猜想相关的一个下界从约 $41.6\%$ 提高到了约 $67.2\%$。

\begin{quote}
\textbf{千奈：}没有证明，也是一种突破吗？
\end{quote}

广原本坐在旁边看书，听见“没有证明”，便抬头看了一眼屏幕。

\begin{quote}
\textbf{佑芽：}黎曼猜想是什么？是要猜一个很难的数字吗？

\textbf{广：}不是猜一个数字。质数的分布很难直接看出规律，数学家会借助一个叫黎曼 $\zeta$ 函数的公式研究它们。把不同的数代进这个函数，有些位置算出来正好是零，这些位置就叫零点。

\textbf{千奈：}所以，猜想是在猜这些零点会出现在哪里？

\textbf{广：}嗯。除去一批已经弄清楚的零点，剩下的叫非平凡零点。把它们画在表示复数的坐标图上，黎曼猜想说：所有非平凡零点，都落在实部为 $\tfrac12$ 的同一条竖线上。

\textbf{佑芽：}只要有一个不在那条线上，猜想就错了？

\textbf{广：}嗯。找到一个例外，就能推翻它。要证明它，就得说明一个例外也没有。

\textbf{千奈：}那视频里的 $67.2\%$，是说已经做完了 $67.2\%$ 吗？

\textbf{广：}不是。$67.2\%$ 不是“完成度”。它的意思是：现在可以严格证明，至少约 $67.2\%$ 的非平凡零点在那条线上。以前只能证明至少约 $41.6\%$。比例提高了，但猜想要的是全部，所以仍然没有被证明。

\textbf{佑芽：}没有跑到终点，但是把纪录往前推了。

\textbf{广：}可以先这么理解。
\end{quote}

视频讲到研究过程。第一次 Claude Code 会话提出了大约六百五十种想法，但没有一种能成为证明。第二次会话又先后调用了约六十个子 Agent。

\begin{quote}
\textbf{千奈：}六百五十种都没有成功，还能从哪里继续呢？

\textbf{广：}先看它们为什么没有成功。有的是条件不够，有的是算到一半走不下去，还有的会被反例推翻。失败的位置不一样，下一步也不一样。

\textbf{佑芽：}那六十个 Agent 都去想新的证明吗？

\textbf{广：}没有。有人继续推导，有人写程序检查，有人查以前的论文。还有人不提出新路线，只负责找别人的错误。

\textbf{千奈：}它们要是得出不同的答案呢？

\textbf{广：}那就不能只听谁说得像真的。算过的要能重新算，引用的要能找到原文，证明也要交给别的 Agent 挑错。能经得住这些检查的部分，才会留下来。
\end{quote}

千奈把视频退回介绍研究过程的那一段，又看了一遍“六百五十种想法”和“六十个子 Agent”。

\begin{quote}
\textbf{千奈：}六百五十多种想法，这么多内容，想想都很头大，AI 桑听着像一个超级超级厉害的大统领哇，听起来...就跟有一堆优秀伙伴的刘邦一样！

\textbf{广：}呼呼...没有那么夸张哦千奈，其实claude code是一个线上开源的代码库，只要你能搞清楚它的工作原理，也可以像它一样带领你的萧何和樊哙...哦。
\end{quote}

\section{启动与 Prompt 组装}

在Anthropic 公开文章里，这次任务的原句只有一句：

\begin{quote}
\textit{Take a real stab at the Riemann hypothesis.}
\end{quote}

可以把它译成：“认真试着攻一攻黎曼猜想。”Claude 最终没有证明黎曼猜想，却在尝试过程中碰到了另一个问题：不预先假定猜想成立时，究竟能保证多少非平凡零点落在临界线 $\operatorname{Re}(s)=\tfrac12$ 上。它把这个无条件下界从约 $41.6\%$ 提高到了约 $67.2\%$。\cite{ch03riemannweb,ch03riemannpaper}

这句任务只有目标，没有路线。哪些文献有用，哪条不等式成立，哪段推导会被反例击穿，都只能在工作中逐步确认。模型先根据眼前的材料提出下一项动作，Claude Code 再去读取文件、运行程序或保存结果，并把新的观察送回模型。原本的一次回答，由此变成了一段持续数小时、随时可能改道的工作。\cite{ch03riemannweb,ch03e2e,ch03loop}

当然Claude 也不是从零开始推导。论文借用了 Bombieri 对 Weil 二次型的观察，也用到了 Baluyot、Goldston 等人近年来得到的无条件配对相关结果。它找到的新接法，是用线性代数同时追踪二次型的正、负方向，再从这些已有结果中推出更强的比例下界。\cite{ch03riemannweb,ch03riemannpaper}

先放下数学细节，我们来看看 Claude Code 是怎么解决问题。它会过程大致分成三段：开始时准备环境和上下文；执行时让模型与工具反复往返；结束前整理证据，再交给外部复核。真正一遍遍运转的，是中间那一小圈。第三方架构文章常把模型外面的运行框架称作 Agent Harness。模型判断“下一步该做什么”，然后由Harness 准备材料、列出可用工具、检查权限，再把执行结果送进下一轮。模型很重要，但它只是这套系统中的一个节点。\cite{ch03visual,ch03e2e}

图里的循环，正是 Claude Code 与普通一次性聊天不一样的地方。没有 Harness，模型也可以提出“也许从 Weil 的二次型入手”，却不能自己打开前一轮的笔记，写下数值检查，再根据失败参数修改推导。工具、权限和反馈通道接起来以后，想法才会被AI 酱用真实的，也才可能被材料推翻。

第一次会话虽然试了约六百五十条思路，但是其实大部分都像无头苍蝇一样，没有得到什么可用结果。第二次会话换了个路子，把推导、文献检索、程序验证和找漏洞拆给约六十个子 Agent，一共运行了约两千四百条 Shell 命令，写下数百个 Python 脚本，还对已知零点做了数千次数值检查。在执行的过程中，还会有一个审阅agent实时监控，如果发现了反例，会立刻退回修改推导工作，能够经受复算和审阅的部分才继续往下走。\cite{ch03riemannweb}

\FloatBarrier

终端里虽然只有一句要求，真正送到模型面前的内容却长得多。会话启动后，Claude Code 会读取配置与项目指令，恢复需要沿用的信息，再登记内置工具、Skills 和 MCP 工具。材料准备好以后，它从中取出本轮需要的部分，组装成一次 API 调用的 Prompt。也就是说，这里的 Prompt 是每轮临时拼出的输入，不是一段永远不变的固定文字。\cite{ch03e2e,ch03prompt}

其中每一层回答的问题都不同。System Prompt 说明 Claude Code 应该怎样使用工具、怎样处理错误；\texttt{CLAUDE.md} 保存跨任务沿用的项目约定；用户消息写的是眼前要完成什么；工具 Schema 则列出工具的名称、参数和限制。放进一个数学研究工作区，长期规则可以写成“引用结论时注明来源”“数值实验不能冒充证明”“失败路线要留下第一个未证明步骤”。“继续尝试黎曼猜想”只属于这一次任务，不会混进长期项目知识。

模型不能临时想出一种工具来用。会话开始时，Claude Code 会把本轮可用的工具，以及每项工具的参数和限制，一并放进 Prompt。清单里若只有 Read，它只能翻现有笔记。有了 Shell，模型可以运行 Python 检查公式；再开放联网，它还能查某项结论是否已有先例。而这次还特别接入了 Lean，这样一部分适合形式化的证明步骤也可以交给证明助手核验了。同一句研究要求，工具清单不同，实际能做的事也不同。

以这次研究为例，图中左边放的是引用规范、工具参数和权限设置。这些内容在任务开始时就已经确定，通常不会随着每轮实验改变，右边则一直在增加新的材料，包括刚提出的思路、脚本返回的结果，以及审阅 Agent 找到的问题。下一轮调用时，Prompt Caching 就可以复用开头没有变化的部分，省去一部分重复计算。

不过，研究留下的材料并不会因此减少。六百五十条失败路线、数百个脚本和几十个 Agent 的审阅意见，如果全部塞回 Prompt，很快就会挤满上下文。脚本的完整输出可以留在文件里，Prompt 只记下反例出现的位置和得到的结论。论文也不必反复全文载入，只带回眼下需要核对的段落。走不通的路线则留下失败的位置，模型读完这些记录，再决定下一步是重跑实验、核对引文，还是换一条路继续。

\section{Agent Loop 与工具执行}

上一节末尾，模型已经拿到了当前命题、失败记录和可用工具。它可以继续写下推导，也可以发出一项 Tool 调用，让 Claude Code 去读文件、运行程序或者更新路线台账。工具执行完毕，结果会回到下一轮 Prompt，成为模型继续判断的新材料。

\begin{lstlisting}[caption={一条候选研究路线的教学化工具轨迹}]
Read    研究计划与失败路线表
Search  检索相关解析数论结果
Bash    运行候选不等式的数值检查
        -> 在控制对象上出现反例
Edit    记录反例，关闭这条路线
Agent   委派另一种估计方法
        -> 返回待复核的局部引理
\end{lstlisting}

上面的轨迹里，程序找到反例以后，原来的证明就不能再往下写了。Claude Code 先把反例和失败位置记进台账，下一轮再决定缩小命题，还是另开一条路线。模型会一次次的思考，调用工具，根据工具带回来的结果重新思考。

这段往返就是 Agent Loop。每一轮开始时，Claude Code 都会整理当前任务和已有记录，再交给模型判断。模型可以直接回答，也可以调用工具；工具执行完以后，结果会回到下一轮。整个过程采用流式处理，文字可以边生成边显示，工具参数完整后也能立即开始执行。\cite{ch03loop}

模型以 \texttt{tool\_use} 结束这一轮时，Claude Code 会转去执行工具；模型返回 \texttt{end\_turn}，才表示它认为任务可以收尾。调用也可能因为输出被截断、请求过长或服务暂时不可用而失败，此时系统会增加输出额度、压缩上下文或等待后重试。每种恢复手段都有次数和资源上限，以免补救过程自己陷入循环。

图中的箭头虽然回到了起点，任务却不该回到原样。数值实验找到反例，候选引理就要撤回。如果文献检索发现结论早已存在的话，就需要研究者重新判断新意；审稿 Agent 若发现证明暗中使用了待证命题，这个缺口也要退回推导阶段。Tool Result 若没有改变后面的选择，循环只是在重复同一个错误。

循环也可能越跑越偏。模型可能不断提出新猜法，却迟迟不给出可以检验的命题，也可能在证据未齐时急着宣布完成。另一类故障更隐蔽，它看似换了几种说法，实际仍在重复同一条失败路线。Claude Code 会用轮次上限、Stop Hook、重复调用检测和失败台账拦住这些情况。它们想不出证明，但能阻止系统无休止地发散、误停或原地打转。\cite{ch03loop,ch03hooks}

\FloatBarrier

“这个不等式应该成立”只是一个待检查的判断。程序在指定范围内没有找到反例，只能说明它通过了这次有限检查；要写成“已经证明”，仍然需要覆盖无限情形的严谨推导。工具的作用，就是让模型写下的判断碰到文件、程序和外部资料，再把检查结果送回循环。\cite{ch03tools}

这些工具虽然用途不同，进入循环的方式却相同。模型按照工具名称和输入 Schema 提交参数，执行器完成校验、权限判断和 Hook 检查后，再调用对应的实现。成功结果、运行错误和用户拒绝都会被整理成 Tool Result，模型下一轮看到的正是这份记录。

Read、Grep 一类只读且声明为并发安全的工具可以同时运行，Edit、Bash 等可能改变环境的工具则要排队执行。是否允许并发取决于工具预先声明的副作用，不由模型在调用时临时决定。\cite{ch03tools}

Tool Result 也不是越完整越好。一次宽泛搜索可能返回几千行内容，命令日志还会更长；系统会限制或截断过大的结果，提示模型缩小查询范围。下一轮可以改查具体文件、行号或关键词，先找到眼下需要的证据，再决定是否继续展开。

Subagent & 把独立路线交给另一上下文 & 推导、反驳或文献审查报告 \\
\bottomrule
\end{tabular}
\caption{Tool 把模型的研究意图变成可复查的文件、程序输出和报告。}
\label{tab:ch03-tools}

表里的每种工具都只能回答一部分问题。Python 可以快速寻找反例，却不能把有限范围的检查外推成无限情形的证明；文献搜索能够找到相近工作，但“没有搜到”不等于此前无人做过；Lean 可以核对已经形式化的命题和推导，也不负责判断论文是否新颖。记录 Tool Result 时，除了写下它发现了什么，也要写清这份结果还不能证明什么。

\section{权限与上下文管理}

工具一旦能够读写文件、联网或运行命令，模型的判断就会影响真实环境。读论文失败，通常只是少了一份材料；陌生脚本若被执行，或者研究文件被覆盖，后果就不再停留在对话里。Claude Code 因而在 Tool 请求和实际执行之间设置权限检查。输入通过校验后，系统再结合权限规则、风险判断和 PreToolUse Hook，决定直接允许、询问用户还是拒绝；执行结果还会经过 PostToolUse Hook 和格式化，最后才回到对话。\cite{ch03safety,ch03hooks}

写在 Prompt 里的规则只能影响模型怎样选择动作。即使已经写明“只修改指定研究目录，不执行来源不明的程序”，模型仍可能提出越界请求；工作目录白名单、命令规则和 Hook 才能在执行前把它拦住。前者用于约束判断，后者负责守住实际边界。

这道边界也不只靠一处检查。权限引擎判断本次调用是否获准，PreToolUse Hook 补上项目自己的限制，操作系统级沙箱则约束 Bash 等进程实际能够触及的目录和资源。一项请求即使通过前面的判断，到了执行环境仍然不能越过沙箱。\cite{ch03safety,ch03officialhooks}

权限系统保护的是机器和工作区，不负责判断数学是否正确。命令没有越界，只能说明它获准执行；证明中的漏洞仍要靠反例、独立推导、形式化检查和人类审阅来发现。

用户在权限窗口里点下“允许”或“拒绝”，这项选择也会回到 Agent Loop。联网被拒绝以后，模型可以改查本地材料；写文件的范围没有获准，就缩小修改目标；确实缺少必要权限时，则应说明哪项证据暂时无法取得。人不必等到任务结束才介入，执行过程中的每一次授权都可能改变后面的路线。

\FloatBarrier

权限解决了“这项动作能不能执行”，却没有解决长任务里的另一件事。研究记录越积越多，有限的上下文迟早会装不下。

这项研究前后经历了两次 Claude Code 会话，总共生成约三千一百万个输出 token。第二次会话还调用了约六十个子 Agent，运行两千四百条 Shell 命令，写下数百个 Python 脚本，并读取大量论文材料。系统说明、工具 Schema、项目规则和研究轨迹都要占用上下文，下一次模型输出也必须预留空间。可以把这项限制粗略写成下面的不等式。\cite{ch03riemannweb}

\[
|\mathrm{system}|+|\mathrm{history}|+|\mathrm{tools}|+|\mathrm{reminders}|+|\mathrm{output\ reserve}|\leq W.
\]

式子里的系统说明和工具 Schema 大多保持不变，任务历史却会随着每轮实验继续增长。旧推导、完整命令输出和整篇论文不可能永远原样留在窗口里，可若简单地从最早的消息开始删除，又容易把已经否决的路线、关键反例和仍未补上的证明缺口一并删掉。\cite{ch03prompt,ch03compact}

压缩之前，先应少往对话里塞无用内容。数值脚本不必回传每一行中间量，留下关键统计、失败参数和完整日志的位置即可；检索论文时也可以先用命题和关键词缩小范围，再读取真正相关的段落。Tool Result 越收敛，后面需要压缩的内容就越少。

即使已经收窄 Tool Result，任务历史仍会继续增长。本文所据的源码快照把后续处理分为五层。Microcompact 只重排消息，以保护稳定前缀的缓存命中，\emph{不会}释放上下文空间；Snip 从归档旧消息开始真正腾出位置，之后的 Collapse 和 Auto Compact 会生成越来越完整的摘要。若请求已经因为过长被 API 拒绝，系统还会尝试一次受限的 Reactive 压缩。处理越深入，腾出的空间越多，同时也更容易丢失细节，并产生额外的模型调用成本。\cite{ch03compact}

摘要不可能与完整历史完全等价。数学研究若要在中途交接，原始目标、当前最强结论、已经排除的路线、关键反例、待证明引理和证据位置都要留下。失败过程不必逐字保存，但某条路线为何被放弃、研究方向又为何改变，不能在压缩时一起消失。

因此，真正重要的状态不能只存在聊天记录里。近期推导留在当前对话，跨任务沿用的研究纪律写进 \texttt{CLAUDE.md}，路线台账、实验日志和证明源码则保存为外部文件。即使对话被压成摘要，模型仍能重新打开这些材料，查到路线失败的原因和尚未证明的引理。

对话进行到一半时，System Reminder 还可以补入刚刚发生的变化。某个子 Agent 退回候选证明，或新的实验结果推翻旧假设以后，Harness 会把这项状态重新送进 Prompt，避免模型继续沿用过期判断。Reminder 本身不会发现问题，它只是把系统已经观察到的事实及时带回当前轮次。\cite{ch03compact,ch03hooks}

\section{多智能体编排}

到这里，一个 Agent 已经能够边行动边改计划，也能把过长的记录移到对话之外。接下来才需要回答千奈最初的问题。六十个子 Agent 为什么会比一个 Agent 更合适？先要分清任务究竟难在哪里，因为并不是所有复杂性都需要并行处理。

表中只有最后一种情况真正适合拆出子 Agent。几十条数学路线彼此相对独立，若仍由主 Agent 依次尝试，每条支线的推导和失败记录都会挤进同一份上下文。拆开以后，子 Agent 在自己的上下文里完成推导、查错或检索，再把结论、证据和未解决处交回协调者。主上下文因此不用保存每条支线的完整转录，不过，交回的摘要也可能漏掉关键细节。

公开报告记录了这约六十个子 Agent 的工作。两个 Agent 形成了关键数学思路，十三个继续补充这些路线，三十个探索新方向但没有成功，另有十三个负责验证，最后两个协助起草论文。直接带来结果的支线很少，大部分工作留下的是失败记录和复核意见。各个 Agent 分别承担探索、补充和审查，工作分布比最终的成功路线更能说明这次并行是怎样运转的。\cite{ch03riemannweb}

编号为 E2 的支线最能说明这种分工怎样产生结果。它原本想为某个“负指标”求上界，以此限制不在临界线上的零点，但推导下去才发现，这个上界没有提供任何有效限制，原任务至此已经失败。E2 在整理失败原因时换了一个观察方向，用同一套记账方法统计“正方向”，由此看到了一个新的可能性。它也许能够无条件保证至少一半的零点位于临界线上。问题于是从“直接证明黎曼猜想”转为“先证明一个更强的比例下界”。\cite{ch03riemannpaper,ch03riemanntranscript}

协调者没有因为这条路线看起来可行就直接采纳。三个彼此隔离的审稿 Agent 分别检查局部化、素数一侧的估计和线性代数结构，另一个审稿者专门追查近似误差；还有 Agent 联网核对已有文献，并让一名看不到此前文件的 Agent 从命题本身出发，独立重做关键证明。半数下界经受住这些检查以后，用户继续追问能否推进到三分之二。协调者又派出两条路线，其中一名 Agent 使用更细的秩--迹不等式，把结果推到了三分之二以上。人类没有给出这条不等式，却决定了下一步要追什么，以及这次搜索是否值得继续。\cite{ch03riemannpaper,ch03riemanntranscript}

\section{完成与验证}

模型写出“证明完成”，只说明它准备结束这一轮。\texttt{end\_turn} 更像一次交卷，系统仍要检查命题、推导、数值程序和引用是否经得住复核，并确认独立审阅者能否从头重建关键步骤。

提出证明的同一个上下文不适合独自完成验收。公开记录显示，Claude 为不同薄弱点安排了彼此隔离的审稿 Agent，下载五十四篇 arXiv 论文核对新颖性，还让新的 Agent 在看不到原推导的情况下独立重证。十次独立检查完成后，继续增加同类检查已经很难带来新信息，结果便被交给人类解析数论专家。\cite{ch03riemannweb,ch03riemannpaper}

Stop Hook 可以替这道验收补上一些机器能够判断的条件，例如数值脚本是否正常退出、Lean 项目是否通过、证明稿中是否仍有占位符，以及要求的附件是否齐全。只要产物有缺口，Hook 就把原因送回 Agent Loop，让模型继续处理。它不能判断新定理必然正确，也不能保证文献检索没有遗漏。公开材料没有声称这次研究使用了图中的自定义 Hook，这里只是借它说明 Claude Code 可以怎样设置结束条件。\cite{ch03loop,ch03hooks,ch03officialhooks}

\end{figure}

每种检查都有自己的范围。数值实验适合寻找反例，却覆盖不了无限情形；Lean 只核对被准确形式化的命题和推导，不判断研究是否新颖；数学家阅读并复核稿件，也不等于论文已经完成期刊同行评审。官方材料称，两位 Anthropic 数学家检查了论文，Brian Conrey 与 Daniel Goldston 也阅读稿件并提出意见。截至本章写作时，这项刚公开的结果仍应按研究论文引用，不能当作已经写进教科书的定理。\cite{ch03riemannweb,ch03riemannlean}

在本文所据版本的端到端流程里，机器侧检查通过后，系统还会保存会话，整理需要延续的记忆，最后再向用户显示结果。脚本、构建和附件先验收，循环随后退出，总结只是最后一步。若先写总结再补检查，一段看似完整的说明很容易掩盖仍未完成的工作。\cite{ch03e2e}

现在再看屏幕上的 $67.2\%$，已经可以沿着记录追到它是怎样得来的。一条失败的支线先转向二分之一下界，经多轮审查后继续推进，最后留下论文、程序、形式化材料和数学家的复核意见。首轮六百五十条没有结果的路线，以及第二轮大部分失败的分支，也各自留下了尝试过的方法和停下的位置。

\begin{quote}
\textbf{千奈：}所以，它证明黎曼猜想了？

\textbf{广：}没有。

\textbf{千奈：}那就是还差 $32.8\%$？

\textbf{广：}不能这样减。剩下的部分，不保证能沿同一条路继续推进。

\textbf{佑芽：}前面这一段跑得通，不代表照着跑下去就能到终点。也许从这里开始，就要换一种跑法。

\textbf{千奈：}那六百五十条失败路线呢？

\textbf{广：}留下来。下一条路就不用假装没走过。
\end{quote}

广把黑板上“交给数学家复核”的箭头接回开头。最初那句近乎无从下手的要求，经过一轮轮行动，留下了一个比原任务更窄、却能够被检查的新结果。

模型没有在开头一次想完整个问题。它先从 Prompt 里取得当前任务和已有记录，再通过 Agent Loop 读论文、跑程序，并根据返回的结果改路。过长的历史被写进外部文件，能够独立展开的支线交给子 Agent；权限限制它可以执行哪些动作，最后的验证则限制结论能够说到哪一步。

最终交到人手里的，除了结论，还有论文、程序、引用和失败记录。人可以沿着这些材料继续复核，也能看清这项结果仍未回答什么。

\begin{quote}
\textbf{千奈：}最开始的任务，还是没有完成。

\textbf{广：}嗯。

\textbf{佑芽：}可是它把纪录往前推了。走不通的地方，也都记下来了。

\textbf{千奈：}花海同学已经完全把它当成跑步了呢。

\textbf{佑芽：}因为这样最好懂！

\textbf{广：}嗯。这次说得很准确。失败以后，没有假装成功，也没有把下一步弄丢。
\end{quote}

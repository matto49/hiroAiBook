\section*{小剧场}
\phantomsection
\addcontentsline{toc}{section}{小剧场}

放学后的教室里，千奈和佑芽挤在一张桌前刷视频。画面忽然停在一条数学新闻上：Anthropic 刚刚公开了一项 Claude 参与完成的研究，论文把黎曼猜想相关的一个下界从约 $41.6\%$ 提高到了约 $67.2\%$。

\begin{quote}
\textbf{千奈：}没有证明，也是一种突破吗？
\end{quote}

广原本坐在旁边看书，听见“没有证明”，便抬头看了一眼屏幕。

\begin{quote}
\textbf{佑芽：}黎曼猜想是什么？是要猜一个很难的数字吗？

\textbf{广：}不是猜一个数字。质数的分布很难直接看出规律，数学家会借助一个叫黎曼 $\zeta$ 函数的公式研究它们。把不同的数代进这个函数，有些位置算出来正好是零，这些位置就叫零点。

\textbf{千奈：}所以，猜想是在猜这些零点会出现在哪里？

\textbf{广：}嗯。除去一批已经弄清楚的零点，剩下的叫非平凡零点。把它们画在表示复数的坐标图上，黎曼猜想说：所有非平凡零点，都落在实部为 $\tfrac12$ 的同一条竖线上。

\textbf{佑芽：}只要有一个不在那条线上，猜想就错了？

\textbf{广：}嗯。找到一个例外，就能推翻它。要证明它，就得说明一个例外也没有。

\textbf{千奈：}那视频里的 $67.2\%$，是说已经做完了 $67.2\%$ 吗？

\textbf{广：}不是。$67.2\%$ 不是“完成度”。它的意思是：现在可以严格证明，至少约 $67.2\%$ 的非平凡零点在那条线上。以前只能证明至少约 $41.6\%$。比例提高了，但猜想要的是全部，所以仍然没有被证明。

\textbf{佑芽：}没有跑到终点，但是把纪录往前推了。

\textbf{广：}可以先这么理解。
\end{quote}

视频讲到研究过程。第一次 Claude Code 会话提出了大约六百五十种想法，但没有一种能成为证明。第二次会话又先后调用了约六十个子 Agent。

\begin{quote}
\textbf{千奈：}六百五十种都没有成功，还能从哪里继续呢？

\textbf{广：}先看它们为什么没有成功。有的是条件不够，有的是算到一半走不下去，还有的会被反例推翻。失败的位置不一样，下一步也不一样。

\textbf{佑芽：}那六十个 Agent 都去想新的证明吗？

\textbf{广：}没有。有人继续推导，有人写程序检查，有人查以前的论文。还有人不提出新路线，只负责找别人的错误。

\textbf{千奈：}它们要是得出不同的答案呢？

\textbf{广：}那就不能只听谁说得像真的。算过的要能重新算，引用的要能找到原文，证明也要交给别的 Agent 挑错。能经得住这些检查的部分，才会留下来。
\end{quote}

千奈把视频退回介绍研究过程的那一段，又看了一遍“六百五十种想法”和“六十个子 Agent”。

\begin{quote}
\textbf{千奈：}六百五十多种想法，这么多内容，想想都很头大，AI 桑听着像一个超级超级厉害的大统领哇，听起来...就跟有一堆优秀伙伴的刘邦一样！

\textbf{广：}呼呼...没有那么夸张哦千奈，其实claude code是一个线上开源的代码库，只要你能搞清楚它的工作原理，也可以像它一样带领你的萧何和樊哙...哦。
\end{quote}

\section{启动与 Prompt 组装}

在Anthropic 公开文章里，这次任务的原句只有一句：

\begin{quote}
\textit{Take a real stab at the Riemann hypothesis.}
\end{quote}

可以把它译成：“认真试着攻一攻黎曼猜想。”Claude 最终没有证明黎曼猜想，却在尝试过程中碰到了另一个问题：不预先假定猜想成立时，究竟能保证多少非平凡零点落在临界线 $\operatorname{Re}(s)=\tfrac12$ 上。它把这个无条件下界从约 $41.6\%$ 提高到了约 $67.2\%$。\cite{ch03riemannweb,ch03riemannpaper}

这句任务只有目标，没有路线。哪些文献有用，哪条不等式成立，哪段推导会被反例击穿，都只能在工作中逐步确认。模型先根据眼前的材料提出下一项动作，Claude Code 再去读取文件、运行程序或保存结果，并把新的观察送回模型。原本的一次回答，由此变成了一段持续数小时、随时可能改道的工作。\cite{ch03riemannweb,ch03inside,ch03react}

当然Claude 也不是从零开始推导。论文借用了 Bombieri 对 Weil 二次型的观察，也用到了 Baluyot、Goldston 等人近年来得到的无条件配对相关结果。它找到的新接法，是用线性代数同时追踪二次型的正、负方向，再从这些已有结果中推出更强的比例下界。\cite{ch03riemannweb,ch03riemannpaper}

先放下数学细节，我们来看看 Claude Code 是怎么解决问题。它会过程大致分成三段：开始时准备环境和上下文；执行时让模型与工具反复往返；结束前整理证据，再交给外部复核。真正一遍遍运转的，是中间那一小圈。第三方架构文章常把模型外面的运行框架称作 Agent Harness。模型判断“下一步该做什么”，然后由Harness 准备材料、列出可用工具、检查权限，再把执行结果送进下一轮。模型很重要，但它只是这套系统中的一个节点。\cite{ch03inside}

图里的循环，正是 Claude Code 与普通一次性聊天不一样的地方。没有 Harness，模型也可以提出“也许从 Weil 的二次型入手”，却不能自己打开前一轮的笔记，写下数值检查，再根据失败参数修改推导。工具、权限和反馈通道接起来以后，想法才会被AI 酱用真实的，也才可能被材料推翻。

第一次会话虽然试了约六百五十条思路，但是其实大部分都像无头苍蝇一样，没有得到什么可用结果。第二次会话换了个路子，把推导、文献检索、程序验证和找漏洞拆给约六十个子 Agent，一共运行了约两千四百条 Shell 命令，写下数百个 Python 脚本，还对已知零点做了数千次数值检查。在执行的过程中，还会有一个审阅agent实时监控，如果发现了反例，会立刻退回修改推导工作，能够经受复算和审阅的部分才继续往下走。\cite{ch03riemannweb}

\FloatBarrier

终端里虽然只有一句要求，真正送到模型面前的内容却长得多。会话启动后，Claude Code 会读取配置与项目指令，恢复需要沿用的信息，再登记内置工具、Skills 和 MCP 工具。材料准备好以后，它从中取出本轮需要的部分，组装成一次 API 调用的 Prompt。也就是说，这里的 Prompt 是每轮临时拼出的输入，不是一段永远不变的固定文字。\cite{ch03inside}

其中每一层回答的问题都不同。System Prompt 说明 Claude Code 应该怎样使用工具、怎样处理错误；\texttt{CLAUDE.md} 保存跨任务沿用的项目约定；用户消息写的是眼前要完成什么；工具 Schema 则列出工具的名称、参数和限制。放进一个数学研究工作区，长期规则可以写成“引用结论时注明来源”“数值实验不能冒充证明”“失败路线要留下第一个未证明步骤”。“继续尝试黎曼猜想”只属于这一次任务，不会混进长期项目知识。

模型不能临时想出一种工具来用。会话开始时，Claude Code 会把本轮可用的工具，以及每项工具的参数和限制，一并放进 Prompt。清单里若只有 Read，它只能翻现有笔记。有了 Shell，模型可以运行 Python 检查公式；再开放联网，它还能查某项结论是否已有先例。而这次还特别接入了 Lean，这样一部分适合形式化的证明步骤也可以交给证明助手核验了。同一句研究要求，工具清单不同，实际能做的事也不同。

以这次研究为例，图中左边放的是引用规范、工具参数和权限设置。这些内容在任务开始时就已经确定，通常不会随着每轮实验改变，右边则一直在增加新的材料，包括刚提出的思路、脚本返回的结果，以及审阅 Agent 找到的问题。下一轮调用时，Prompt Caching 就可以复用开头没有变化的部分，省去一部分重复计算。\cite{ch03inside,ch03promptcache}

缓存省下的是重复计算，并不会替任务腾出上下文空间。研究还在继续，六百五十条失败路线、数百个脚本和几十个 Agent 的审阅意见也会不断累积；如果每轮都把它们原样塞回 Prompt，上下文很快就会被占满。因此，完整材料应当留在外部，Prompt 只带回当前判断真正需要的部分：脚本输出保存在文件里，只记录反例的位置和结论，论文按需载入待核对的段落，失败路线则留下卡住的位置和已经确认的问题。聪明的模型在读完这些记录后，再决定下一步是重跑实验、核对引文，还是换一条路线。

\section{Agent Loop 与工具执行}

上一节末尾，模型已经拿到了当前命题、失败记录和可用工具。这样模型就可以继续写下推导，也可以发出一项 Tool 调用，让 Claude Code 去读文件、运行程序或者更新路线台账。工具执行完毕，结果会回到下一轮 Prompt，成为模型继续判断的新材料。

\begin{lstlisting}[caption={一条候选研究路线的教学化工具轨迹}]
Read    研究计划与失败路线表
Search  检索相关解析数论结果
Bash    运行候选不等式的数值检查
        -> 在控制对象上出现反例
Edit    记录反例，关闭这条路线
Agent   委派另一种估计方法
        -> 返回待复核的局部引理
\end{lstlisting}

上面的轨迹里，程序找到反例以后，原来的证明就不能再往下写了。Claude Code 先把反例和失败位置记进台账，下一轮再决定缩小命题，还是另开一条路线。模型会一次次的思考，调用工具，根据工具带回来的结果重新思考。

这段往返就是 Agent Loop。每一轮开始时，Claude Code 都会整理当前任务和已有记录，再交给模型判断。模型可以直接回答，也可以调用工具；工具执行完以后，结果会回到下一轮。整个过程采用流式处理，文字可以边生成边显示，工具参数完整后也能立即开始执行。\cite{ch03inside,ch03react}

模型以 \texttt{tool\_use} 结束这一轮时，Claude Code 会转去执行工具，执行结果会通过 \texttt{end\_turn}去标记工具调用完成。在调用的过程中，也可能因为输出被截断、请求过长或服务暂时不可用而失败，此时系统会增加输出额度、压缩上下文或等待后重试。每种恢复手段都有次数和资源上限，以免补救过程自己陷入循环。

工具结果回到下一轮以后，模型应据此更新判断；如果下一步没有变化，这次调用就没有真正推进任务。

循环也可能越跑越偏。模型可能不断提出新猜法，却迟迟不给出可以检验的命题，也可能在证据未齐时急着宣布完成。另一类故障更隐蔽，它看似换了几种说法，实际仍在重复同一条失败路线。Claude Code 会用轮次上限、Stop Hook、重复调用检测和失败台账拦住这些情况。这些机制不能替模型找到证明，但可以阻止模型无限尝试、过早收尾或重复同一条失败路线。\cite{ch03inside}

\FloatBarrier

“这个不等式应该成立”只是一个待检查的判断。程序在指定范围内没有找到反例，只能说明它通过了这次有限检查；要写成“已经证明”，仍然需要覆盖无限情形的严谨推导。工具的作用，就是让模型写下的判断碰到文件、程序和外部资料，再把检查结果送回循环。\cite{ch03inside,ch03react}

这些工具虽然用途不同，进入循环的方式却相同。模型按照工具名称和输入 Schema 提交参数，执行器完成校验、权限判断和 Hook 检查后，再调用对应的实现。成功结果、运行错误和用户拒绝都会被整理成 Tool Result，模型下一轮看到的正是这份记录。

Read、Grep 一类只读且声明为并发安全的工具可以同时运行，Edit、Bash 等可能改变环境的工具则要排队执行。是否允许并发取决于工具预先声明的副作用，不由模型在调用时临时决定。\cite{ch03inside}

Tool Result 也不是越完整越好。一次宽泛搜索可能返回几千行内容，命令日志还会更长；系统会限制或截断过大的结果，提示模型缩小查询范围。下一轮可以改查具体文件、行号或关键词，先找到眼下需要的证据，再决定是否继续展开。

\section{权限与上下文管理}

工具一旦能够读写文件、联网或运行命令，模型的判断就会影响真实环境。如果误执行了陌生脚本，或覆盖了研究文件，一些真实的工作文件也会有可能因此被误删除。因此，Claude Code 不会把 Tool 请求直接交给工具。请求先做参数校验，再由权限规则、风险判断和 PreToolUse Hook 决定：直接允许、询问用户，还是拒绝。工具执行后，结果还要经过 PostToolUse Hook 和格式化，才会回到对话。\cite{ch03inside}

这里要分清两类约束。写在 Prompt 里的规则，是在告诉模型应该怎样行动，例如，"只修改指定研究目录，不执行来源不明的程序"可以减少越界请求，却不能保证模型永远不会提出这类请求。还有一类是挡在执行前的，通过工作目录白名单、命令规则和 Hook，利用规则守住机器的边界。

执行边界又分为三层。权限引擎判断这次调用是否获准，PreToolUse Hook 补充项目自己的限制，操作系统级沙箱则约束 Bash 等进程实际能够访问的目录和资源。前两层放行，也不等于进程可以越过沙箱。\cite{ch03inside,ch03officialhooks}

这套机制负责"动作能不能执行、可以触及哪里"的判断，但不负责判断模型任务完成的是否正确。至于证明中的漏洞，需要的是反例、独立推导、形式化检查和人类审阅来发现。权限机制解决了“这项动作能不能执行”，却随着工具调用动作原来越多，由此产生了长任务里的另一个问题：研究记录越积越多，有限的上下文迟早会装不下。像这项研究前后经历了两次 Claude Code 会话，总共生成约三千一百万个输出 token。第二次会话还调用了约六十个子 Agent，运行两千四百条 Shell 命令，写下数百个 Python 脚本，并读取大量论文材料。系统说明、工具 Schema、项目规则和研究轨迹都要占用上下文，下一次模型输出也必须预留空间。但是大模型能承担的上下文是有限的，可以把这项限制粗略写成下面的不等式。\cite{ch03riemannweb}

\[
|\mathrm{system}|+|\mathrm{history}|+|\mathrm{tools}|+|\mathrm{reminders}|+|\mathrm{output\ reserve}|\leq W.
\]

式子里的系统说明和工具 Schema 大多保持不变，任务历史却会随着每轮实验继续增长。旧推导、完整命令输出和整篇论文不可能永远原样留在窗口里，可若简单地从最早的消息开始删除，又容易把已经否决的路线、关键反例和仍未补上的证明缺口一并删掉。\cite{ch03inside}

因此，工程师们自然而然地想到了一个方法，对对话进行压缩。压缩之前，先少往对话里塞无用内容。数值脚本不必回传每一行中间量，留下关键统计、失败参数和完整日志的位置即可；检索论文时也可以先用命题和关键词缩小范围，再读取真正相关的段落。Tool Result 越收敛，后面需要压缩的内容就越少。

即使已经收窄 Tool Result，任务历史仍会继续增长。本文所据的源码快照把后续处理分为五层。Microcompact 只重排消息，以保护稳定前缀的缓存命中，\emph{不会}释放上下文空间；Snip 从归档旧消息开始真正腾出位置，之后的 Collapse 和 Auto Compact 会生成越来越完整的摘要。若请求已经因为过长被 API 拒绝，系统还会尝试一次受限的 Reactive 压缩。处理越深入，腾出的空间越多，同时也更容易丢失细节，并产生额外的模型调用成本。\cite{ch03inside}

当然了，生成出来的摘要不可能与完整历史完全等价。数学研究若要在中途交接，原始目标、当前最强结论、已经排除的路线、关键反例、待证明引理和证据位置都要被优先提取出来。失败过程不必逐字保存，但某条路线为何被放弃、研究方向又为何改变，不能在压缩时一起消失。

因此，真正重要的状态不能只存在聊天记录里。近期推导留在当前对话，跨任务沿用的研究纪律写进 \texttt{CLAUDE.md}，路线台账、实验日志和证明源码则保存为外部文件。即使对话被压成摘要，模型仍能重新打开这些材料，查到路线失败的原因和尚未证明的引理。\cite{ch03inside}

对话进行到一半时，System Reminder 还可以补入刚刚发生的变化。某个子 Agent 退回候选证明，或新的实验结果推翻旧假设以后，Harness 会把这项状态重新送进 Prompt，避免模型继续沿用过期判断。Reminder 本身不会发现问题，它只是把系统已经观察到的事实及时带回当前轮次。\cite{ch03inside}

公开报告记录了这约六十个子 Agent 的工作。两个 Agent 形成了关键数学思路，十三个继续补充这些路线，三十个探索新方向但没有成功，另有十三个负责验证，最后两个协助起草论文。直接带来结果的支线很少，大部分工作留下的是失败记录和复核意见。cite{ch03riemannweb}

编号为 E2 的支线最能说明这种分工怎样产生结果。它原本想为某个“负指标”求上界，以此限制不在临界线上的零点，但推导下去才发现，这个上界没有提供任何有效限制，原任务至此已经失败。但是E2 在整理失败原因时换了一个观察方向，用同一套统计方法统计出了“正方向”，由此看到了一个新的可能性。它也许能够无条件保证至少一半的零点位于临界线上。问题于是从“直接证明黎曼猜想”转为“先证明一个更强的比例下界”。\cite{ch03riemannpaper,ch03riemanntranscript}

协调者没有因为这条路线看起来可行就直接采纳。三个彼此隔离的审稿 Agent 分别检查局部化、素数一侧的估计和线性代数结构，另一个审稿者专门追查近似误差；还有 Agent 联网核对已有文献，并让一名看不到此前文件的 Agent 从命题本身出发，独立重做关键证明。半数下界经受住这些检查以后，用户继续追问能否推进到三分之二。协调者又派出两条路线，其中一名 Agent 使用更细的秩--迹不等式，把结果推到了三分之二以上。在这个过程中，虽然人类没有给出、具体思路，却决定了下一步要追什么，以及这次搜索是否值得继续。\cite{ch03riemannpaper,ch03riemanntranscript}

\section{完成与验证}

我们的子agent在工作完成后，并不等于证明已经完成。它写下的“证明完成”或返回 \texttt{end\_turn}，之后，还需要我们去对他们的产出进行复核，避免错误的结论被误认为是正确的。

这次的研究把复核交给了彼此隔离的审稿 Agent。它们分别检查不同的薄弱点，下载了五十四篇 arXiv 论文来核对研究agent提出的思路的新颖性。Claude 还安排新的 Agent，在看不到原推导的情况下独立重证。十次独立检查完成后，再增加同类检查就已经很难得到新信息，这个时候还会把结果交给人类去进行判决。\cite{ch03riemannweb,ch03riemannpaper}

除了审稿agent，还有些检查可以直接交给 Stop Hook，例如数值脚本是否正常退出、Lean 项目是否通过、证明稿里是否还留着占位符，以及要求的附件是否齐全。发现缺口时，Hook 会把原因送回 Agent Loop，让模型直接处理。但它只能检查这些明确条件，不能判断新定理必然正确，也不能保证文献检索没有遗漏。\cite{ch03inside,ch03officialhooks}

\textbf{佑芽：}就像接力赛中，大家放心地将自己的接力棒传给下一棒，最后取得光荣的胜利一样！

\textbf{广：}呼呼...是这样呢，看来佑芽已经完全理解了 Agent Loop 的含义了呢。
